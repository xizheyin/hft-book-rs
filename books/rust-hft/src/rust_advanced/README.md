# Rust 语义与抽象成本 (Rust Cost Model)

本部分讨论 Rust 中最容易被当作“语法细节”、但实际上决定工程上界的一组语言机制。生命周期、泛型、宏、内部可变性、Send/Sync 和错误处理，并不是彼此独立的专题；它们共同决定了程序如何表达所有权、如何建立抽象边界，以及如何把运行时代价尽可能前移到编译期。

如果说系统基础部分关注“机器为什么这样运行”，那么这一部分关注“Rust 允许我们怎样组织代码，才能把这些运行时成本约束在可分析的范围内”。

本部分涵盖：
- **生命周期与所有权**：在零拷贝解析和复杂数据结构中的应用。
- **泛型与 Const Generics**：如何利用编译期计算消除运行时开销。
- **宏编程**：使用声明宏和过程宏生成高性能样板代码。
- **智能指针**：`Box`, `Rc`, `Arc` 等抽象在不同访问模式下的取舍。
- **错误处理**：如何在不牺牲性能的前提下构建健壮的错误处理机制。

## 知识体系导航 (Competency Map)

我们将 Rust 的高级特性按照 **高性能系统程序设计的三项核心能力** 进行重组，而非按照语法书的章节排列。

### 1. Zero-Overhead Abstraction (零成本抽象)
> **核心目标**：让抽象不引入超出低层等价实现的非必要成本；是否达到目标要用分配、汇编、代码体积与端到端基准验证。

*   **[泛型与单态化 (Generics & Monomorphization)](generics.md)**
    *   **原理**: 编译器为每个具体类型生成专用代码。
    *   **系统实践**: 在类型集合固定的热路径评估泛型，换取静态分发与内联机会；同时关注代码膨胀。
*   **[常量泛型 (Const Generics)](generics.md)**
    *   **原理**: 将数值（如数组长度）提升为类型的一部分。
    *   **系统实践**: 构建定长 Ring Buffer，让编译器优化边界检查与索引计算。
*   **[GATs (泛型关联类型)](generics.md)**
    *   **原理**: 允许关联类型携带生命周期参数。
    *   **系统实践**: 实现流式迭代器 (Streaming Iterator)，支持零拷贝的 `next()`。
*   **[宏编程 (Macros)](macros.md)**
    *   **原理**: 编译期的代码生成器。
    *   **系统实践**: 批量生成协议解析器与样板接口，减少重复代码。

### 2. Memory Efficiency (内存效率)
> **核心目标**：让布局、分配和生命周期符合访问模式，减少已经被测量为瓶颈的分配、复制与指针追逐。

*   **[所有权与生命周期 (Ownership & Lifetimes)](lifetimes.md)**
    *   **Zero-copy**: 使用 `&str` / `&[u8]` 代替 `String` / `Vec`，直接引用网络缓冲区。
    *   **Cow (写时复制)**: 借用为主、少量输入需要拥有或规范化时的候选方案。
    *   **PhantomData**: 在不增加内存占用的前提下，携带逻辑状态或修补指针生命周期。
*   **[智能指针与分配器 (Smart Pointers)](smart_pointers.md)**
    *   **Box**: 堆分配。热路径慎用，初始化阶段可用。
    *   **Allocator API**: 使用 Arena (Bump) 分配器，降低通用分配器的路径开销。
    *   **Niche Optimization**: 利用类型空位（如 `Option<&T>` 大小等于 `&T`），实现空间压缩。

### 3. Concurrency & Safety (并发与安全)
> **核心目标**：先用所有权和分片减少共享，再为剩余共享状态选择可证明、可测量的同步机制。

*   **[内部可变性 (Interior Mutability)](interior_mutability.md)**
    *   **Cell**: 单线程共享引用下的整体取值/替换；不提供跨线程原子性。
    *   **RefCell**: 运行时借用检查。热路径慎用。
    *   **UnsafeCell**: 一切并发原语的基石。
*   **[Send & Sync](send_sync.md)**
    *   **Send**: 所有权能否转移至其他线程。
    *   **Sync**: 引用能否在多线程间共享。
    *   **系统实践**: 明确哪些数据应该线程私有，哪些状态可以跨核传递。
*   **[错误处理 (Error Handling)](error_handling.md)**
    *   **Result**: 显式的值语义错误通道，布局和分支成本取决于 `T`、`E` 与调用方式。
    *   **Panic=Abort**: 可选的进程级失败策略；采用前必须设计订单状态恢复、审计与看门狗。
