# HFT 面试术语表

术语表不是让你背英文缩写，而是帮你在面试中用一句准确的话建立共同语境。真实规则因资产类别和交易场所而异；下面给出的是通用直觉，涉及实现时仍需查目标场所规范。

## 市场与价格

| 术语 | 一句话解释 | 常见追问 |
|---|---|---|
| Bid（买价） | 买方当前愿意支付的价格 | Best Bid 与买一有什么区别？ |
| Ask / Offer（卖价） | 卖方当前愿意接受的价格 | 为什么 Ask 通常高于 Bid？ |
| BBO | 单一场所的最优买价与最优卖价 | BBO 与跨场所 NBBO 有何区别？ |
| Spread（价差） | 最优卖价减最优买价 | Tick size 怎样影响 spread？ |
| Mid-price（中间价） | `(best_bid + best_ask) / 2` 的简单参考价 | 为什么它不保证可成交？ |
| Microprice | 结合买卖盘不平衡调整的短期参考价 | 深度不可靠时会怎样？ |
| Tick Size | 允许报价的最小价格步长 | 过大或过小分别有什么影响？ |
| Liquidity（流动性） | 以较低冲击快速成交的能力 | 只看挂单量够不够？ |
| Market Impact | 自己的交易对市场价格造成的影响 | 临时冲击与永久冲击如何区分？ |
| Slippage（滑点） | 预期价格与实际成交价格的差异 | 延迟、深度和订单类型怎样造成滑点？ |
| Volatility（波动） | 价格变化幅度的统计描述 | 高波动为什么会放大库存风险？ |

## 订单与撮合

| 术语 | 一句话解释 | 常见追问 |
|---|---|---|
| Market Order | 以当前可得价格尽快成交，不保证成交价 | 为什么大单可能跨多档成交？ |
| Limit Order | 只在指定价格或更优价格成交，不保证成交 | 何时会立即成为 Taker？ |
| IOC | 能立即成交的部分成交，其余取消 | 与 FOK 的差别是什么？ |
| FOK | 必须立即全部成交，否则全部取消 | 撮合前怎样判断“全部可成”？ |
| Post-Only | 若会立即吃单则按场所规则拒绝或调整，意图是只提供流动性 | 为什么不能笼统说“一定返佣”？ |
| GTC / DAY | 分别表示持续有效到取消，或仅当日有效 | 日切和交易阶段如何影响状态？ |
| Maker | 向订单簿提供可成交的静态流动性的一方 | Maker 是否一定赚钱？ |
| Taker | 主动与簿中订单成交、消耗流动性的一方 | 成交成本包含哪些部分？ |
| Price-Time Priority | 先比较价格，同价再按时间排队 | Replace 后会不会丢队列位置？ |
| Pro-Rata | 同价订单按数量等规则分配成交 | 为什么大挂单可能更有优势？ |
| Partial Fill | 一个订单只成交了部分数量 | LeavesQty、CumQty 怎样变化？ |
| Self-Trade Prevention | 避免同一主体的买卖订单彼此成交 | 取消哪一边由什么决定？ |

## 订单簿与行情

| 术语 | 一句话解释 | 常见追问 |
|---|---|---|
| L1 | 只包含最优买卖价及通常对应数量 | 能否从 L1 恢复完整深度？ |
| L2 | 按价格档聚合的深度 | 同价订单的排队信息去哪了？ |
| L3 | 逐订单级别的公开订单事件或状态 | 所有市场都会发布 L3 吗？ |
| Snapshot | 某个时点的完整或较完整状态 | 如何和增量消息对齐？ |
| Incremental Update | 只发送相对上个状态的变化 | 丢一条为何会污染后续状态？ |
| Sequence Number | 用于发现缺口、重复和顺序问题的编号 | 序号作用域是包、消息还是通道？ |
| Gap（缺口） | 观察到的序号不连续 | 缺口期间策略应怎样降级？ |

| Book Crossing | 本地出现 `best_bid >= best_ask` 等异常状态 | 一定是丢包吗？也可能是什么阶段？ |

## 延迟与性能

| 术语 | 一句话解释 | 常见追问 |
|---|---|---|
| Latency | 一个操作或链路从起点到终点的耗时 | 起止点用什么时钟、在哪一层打点？ |
| Throughput | 单位时间完成的工作量 | 吞吐提高为何可能伤害单条延迟？ |
| Tail Latency | 分布尾部的高分位耗时，如 P99/P99.9 | coordinated omission 会怎样美化结果？ |
| Jitter | 延迟随时间的波动 | 调度、中断、页错误各如何造成 jitter？ |
| Hot Path | 对关键结果和端到端延迟最敏感的执行路径 | 怎样证明某段代码真在热路径？ |
| Latency Budget | 将端到端目标拆给各阶段的可验收预算 | 阶段独立 P99 能否直接相加？ |
| Cache Line | CPU 缓存与一致性传输的基本块之一，常见为 64 字节但须看硬件 | 为什么两个变量会产生伪共享？ |
| False Sharing | 不同核心写同一缓存行中的不同数据造成一致性流量 | 对齐为何不是免费优化？ |
| NUMA | 不同 CPU/内存节点的访问成本不一致 | first-touch 与线程迁移有什么影响？ |
| Kernel Bypass | 让数据路径绕过部分传统内核网络栈 | 性能收益换来了哪些运维成本？ |
| Busy Polling | 循环检查事件以减少唤醒延迟 | 空闲功耗、核心占用与公平性如何？ |
| Zero-Copy | 避免一个或多个数据复制步骤 | “零拷贝”在哪两个缓冲区之间？ |
| Backpressure | 下游变慢时对上游施加的流量控制 | 行情与订单链路能否采用同一策略？ |

## 三组最容易混淆的概念

### Ack、Fill、Trade

- **Ack**：场所接受订单进入后续处理，不代表已经成交。
- **Fill**：你的订单获得了部分或全部成交。
- **Trade**：市场发生的一笔成交事件；公开行情中的 trade 未必能直接映射为你的 fill。

### 行情正确、策略正确、执行正确

- 行情正确：本地视图与消息语义一致，缺口已识别并恢复。
- 策略正确：给定相同输入和状态，产生符合设计的意图。
- 执行正确：经过风控、路由和会话后，订单状态与场所一致。

三者必须分别验证。“最终持仓对了”不能证明中途没有重复报单或短暂越限。

### 精度、准确度、分辨率

- **分辨率**：时钟能表示的最小刻度。
- **精度**：多次测量的离散程度。
- **准确度**：测量值与真实值的接近程度。

一个能显示纳秒的 API，不代表系统时间戳真的具有纳秒准确度。
