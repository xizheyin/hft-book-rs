# 算法笔试与面试：从“读懂题”到“写对代码”

算法题最让初学者难受的地方，通常不是某个语法不会，而是不知道第一步该做什么：题目很长，脑中似乎有几个办法，却不知道怎样验证，也不知道什么时候可以开始写代码。

这一部分把算法题拆成一套可以重复执行的流程。我们先用语言无关的伪代码说明思路，再把它翻译成可独立编译运行的 C++20 程序。目标不是背下某道题的答案，而是逐渐形成下面这条链路：

```text
读懂题意
  → 明确输入、输出和约束
  → 写出一定正确的暴力办法
  → 找出重复工作
  → 选择数据结构并写下不变量
  → 用伪代码确认控制流程
  → 翻译为 C++20
  → 用边界测试主动找错
  → 解释正确性和复杂度
```

## 1. 事实边界：这是训练框架，不是“公司真题”

不同公司、岗位、面试轮次和年份的考查方式都可能变化。公开招聘说明通常只能帮助我们判断岗位需要哪些能力，不能证明某道网上题目一定是真题，也不能证明面试官一定接受某种语言。

因此，这一部分遵守三个边界：

- 不把未经公司确认的回忆题写成“官方真题”；
- 不承诺“掌握这些题就能覆盖某家公司多少比例”；
- 不猜测 DeepSeek、九坤或任何团队未公开的内部题库、评分规则和实现技术。

准备实际面试时，应以最新岗位说明、笔试通知和招聘方给出的语言限制为准。如果允许自选语言，选择你能最稳定写对、讲清和测试的语言；本书使用 C++20，是为了连接前面的现代 C++ 学习路线和量化开发场景，并不表示每个岗位都要求 C++。

## 2. 笔试与现场面试有什么不同

两者考查的核心能力相通，但时间分配和表达方式不同。

| 场景 | 你主要在证明什么 | 常见风险 |
|---|---|---|
| 在线笔试 | 能在限制时间内提交正确、复杂度合适的程序 | 输入输出格式错、边界漏掉、只过样例、整数溢出 |
| 现场编码 | 能与面试官共同澄清问题，并让思路、代码和验证过程可跟随 | 沉默写代码、过早优化、没有说明假设、不会手工测试 |
| 白板或共享文档 | 不依赖 IDE 也能保持结构清楚 | 括号和变量名混乱、忘记库接口、无法解释为什么正确 |

笔试中，评测程序只看输出，不会因为“思路大致正确”给你补全边界。现场面试中，面试官还会观察你怎样处理不确定性：你是否先确认重复元素、空输入、数值范围和复杂度目标，而不是偷偷做出假设。

可以把二者的共同目标记成一句话：

> 写出满足题意的程序，并让别人有理由相信它对所有合法输入都成立。

## 3. 固定解题流程：每道题都按这九步走

### 第一步：用一句白话复述题意

不要复读原文。把它改写成“给我什么、我要返回什么”。例如：

```text
给我一组整数和一个目标值；
我要判断其中是否有两个不同位置的数，相加正好等于目标值。
```

如果连这句话都说不清，先不要写代码。

### 第二步：确认输入、输出和约束

至少问或检查：

- 输入能否为空？
- 元素能否重复、为负数或为零？
- 要返回“是否存在”、一组下标，还是所有答案？
- 同一个位置能否使用两次？
- 输入是否已经有序？是否允许修改？
- 数量级是几十、十万还是十亿？
- 相加、相乘或计数会不会超过 32 位整数？

约束不是附属信息。它决定 `O(n²)` 是否能接受，也决定是否需要 `std::int64_t`。

### 第三步：手算一个正常样例和一个边界样例

正常样例帮助确认你理解了目标；边界样例更容易暴露隐藏假设。例如空数组、只有一个元素、全部相同、答案在首尾、答案不存在。

### 第四步：先写暴力基线

暴力办法通常更接近题意，也更容易证明。它有三个价值：

1. 确认你确实会解决问题，而不是只认出了题型名称；
2. 给出一个正确性参照，之后可与优化版随机对比；
3. 帮助看清重复做了哪些工作。

暴力不等于最终提交，但也不应因“看起来不高级”而跳过。

### 第五步：找重复工作，写出关键观察

常见观察包括：

- 输入有序，所以一次比较能排除一半范围；
- 只需要知道某个值是否见过，因此可以用集合；
- 窗口每次只移入和移出少量元素，无需从头统计；
- 只关心最大的 `k` 个元素，无需完整排序；
- 当前选择只依赖一个更小的同类问题，可以定义状态转移。

不要只说“用哈希表”或“用动态规划”。先说它消除了哪部分重复工作。

### 第六步：写不变量和伪代码

**不变量**是在循环或递归推进过程中始终成立的事实。例如：

```text
开始处理 values[i] 之前，seen 恰好包含 values[0..i) 中出现过的值。
```

伪代码只表达算法步骤，不绑定 C++ 语法。本文统一使用半开区间 `[left, right)`：包含 `left`，不包含 `right`。

```text
创建空集合 seen
依次读取每个 value：
    needed = target - value
    如果 needed 在 seen 中：
        返回 true
    把 value 放入 seen
返回 false
```

### 第七步：解释为什么正确，再写 C++

一个简短的正确性说明通常包含三部分：

1. **初始化**：循环开始前，不变量为什么成立；
2. **保持**：执行一轮后，不变量为什么继续成立；
3. **终止**：循环结束或提前返回时，怎样推出最终答案。

写代码时，让变量名对应伪代码中的概念。不要在翻译阶段突然换一种算法。

### 第八步：分析时间和额外空间

复杂度描述输入增大时工作量怎样增长，不是一次运行的纳秒数。回答时说明：

- `n` 表示什么；
- 时间是最坏、平均还是摊销；
- 额外空间是否包含返回结果；
- 使用哈希表时，平均情况与最坏情况是否不同。

### 第九步：主动测试，再讨论优化

至少检查：

- 最小合法输入；
- 答案在开头或结尾；
- 没有答案；
- 重复元素；
- 负数、零和极值；
- 题目特别说明的异常情况。

如果还有时间，再讨论替代方案、内存权衡和输入变化。不要在基本正确性尚未建立时先谈 SIMD（单条指令并行处理多份数据）、无锁或微秒级优化。

## 4. 怎样阅读这一部分

如果你很久没有写 C++，推荐顺序是：

1. 先完成 [C++ 基础复习](../cpp/basics_refresher.md)中的快速诊断；
2. 阅读[从题意到程序](problem_solving.md)，建立固定解题动作；
3. 阅读[复杂度、正确性与不变量](complexity_correctness.md)，学会解释为什么对；
4. 阅读[C++20 算法题工具箱](cpp_toolbox.md)，恢复常用容器和标准算法手感；
5. 再进入数组、字符串、树、图、搜索和动态规划等题型章节。

时间紧时也不要完全跳过前三章。做题数量很多但无法解释正确性，遇到题目换皮后仍会卡住。

### 先看优先级，不要把目录当成必学清单

本部分用三档优先级控制学习范围：

| 标记 | 含义 | 对本书目标岗位的要求 |
|---|---|---|
| **P0 主线** | 高频基础，后面的系统题也会反复使用 | 要能从空白实现、解释不变量并测试 |
| **P1 岗位常用** | 基础设施、低延迟或量化开发常见，但不是每轮都考 | 根据岗位说明选择，至少做到能识别和讨论 |
| **P2 选读** | 更偏专项算法轮或竞赛，普通系统/HFT 面试收益较低 | 只有岗位明确要求、模拟暴露缺口或个人时间充足时再学 |

优先级不是“知识高级程度”，也不是对所有公司的预测。它只是回答一个实际问题：**在准备时间有限时，什么应该先练到能独立写，什么只需知道入口，什么可以放心跳过。** 若 P0 仍不稳定，不应为了显得知识面广而先背 KMP、区间 DP、线段树、SCC 或负边最短路。

不需要一天读完。按“方法 → 高频线性结构 → 非线性结构 → 场景与模拟”的顺序推进：

几处重复是有意的，但目的不同：Top-K 在工具箱中练 C++ 翻译，在结构章中练堆不变量，在场景章中练业务约束，在模拟卷中做闭卷验收；DP 入门章解释“为什么选贪心或 DP”，模式章只供需要更多 DP 训练的人继续深入。若前一处已经达到闭卷标准，后面的重复示例可以直接当自测，不必逐行再读。

每个核心模式先精做一两道母题，再做换皮变体。首轮目标不是堆几百道题，而是让常用模式达到“能解释、能写、能测、能应对追问”。

## 6. 三档训练标准

| 层次 | 达标表现 | 暂时不达标的信号 |
|---|---|---|
| 基础 | 能写出暴力办法并处理样例 | 只能说出题型名，无法独立写循环 |
| 面试可用 | 能优化、说明不变量和复杂度，并写出边界测试 | 代码能跑但不知道为什么不会漏解 |
| 稳定 | 能比较多个方案，识别约束变化，并在限时内完成 | 一换返回值、数据范围或输入顺序就要重背答案 |

对零基础读者，先让基础层稳定，再追求速度。第一次独立写对一道普通题花一小时并不可耻；真正需要警惕的是看答案五分钟后误以为自己已经会了。

## 7. 一次练习应该留下什么

每道做过的题建议只保存一张简短错题卡：

```text
题目：
我第一次卡在哪里：读题 / 思路 / 证明 / C++ / 边界
暴力复杂度：
关键观察：
不变量：
最终复杂度：
漏掉的边界：
隔天闭卷重写结果：
```

错题卡的重点不是复制完整代码，而是记录“为什么当时没想到或没写对”。同一道题在隔天和一周后各闭卷重写一次，通常比当天连续看三遍答案更有效。

## 8. 本部分的代码约定

- 完整 `cpp` 代码块都是独立源文件，各自包含所需头文件和 `main`；
- `cpp,ignore` 表示局部片段、接口示意或故意错误，不能单独编译；
- 基线使用 C++20，编译时打开常用警告；
- 教学代码优先清楚和可验证，不假装是生产级低延迟实现；
- `assert` 用于示例自测，不代替线上输入校验和错误处理。

```bash
c++ -std=c++20 -Wall -Wextra -Wpedantic main.cpp -o main
./main
```

当你能稳定执行“复述 → 基线 → 观察 → 不变量 → 伪代码 → C++ → 测试”这条链路时，算法题就不再是一堆互不相关的谜语，而是同一套推理方法在不同数据结构上的应用。
