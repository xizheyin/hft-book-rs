# 算法训练计划：从“看得懂”到限时独立写出

算法准备最常见的误区，是把“刷过多少题”当成能力。真实笔试和面试检查的是：面对没见过的包装，你能否澄清约束、构造基线、找到不变量、写出正确 C++，并用测试和复杂度说明负责到底。

> 本章给出 8 周完整版、28 天压缩版和 14 天应急版。计划服务于 DeepSeek、九坤及相近岗位的通用能力准备，不承诺录用概率，也不能代替岗位要求中的系统、数学、机器学习、项目经历和沟通训练。

这里的“完整版”指完整训练闭环，不是把目录中的每个算法都学一遍。默认先完成 [P0 主线](coverage_matrix.md)；P1 由岗位与模拟结果选择，P2 可以全部跳过。对 HFT/基础设施岗位，如果算法 P0 已稳定，继续刷冷门算法的收益通常低于补操作系统、网络、并发、C++ 生命周期和项目讲解。

## 1. 先定义“准备好”

准备好不是“见过这道题”，而是同一核心模式能通过四级验收：

| 等级 | 你能做什么 | 验收方式 |
|---|---|---|
| A：理解 | 能手算样例，说出输入输出 | 不看答案画状态变化 |
| B：思路 | 能写伪代码、不变量和复杂度 | 10 分钟纸上完成 |
| C：实现 | 能从空白文件写出 C++20 | 编译器、定向测试与 Sanitizer |
| D：迁移 | 需求变化后仍能调整 | 改成流式、返回路径、处理重复或限制内存 |

只有达到 C 才算“会做”，达到 D 才更接近面试中的稳定发挥。

## 2. 开始前 90 分钟诊断

不要提前看题型标签，按顺序完成：

1. **15 分钟**：写函数返回数组中两个数之和等于目标的下标；说明重复值和无解语义。
2. **15 分钟**：对有序数组写“第一个不小于目标”的二分查找。
3. **20 分钟**：合并重叠区间，给出时间复杂度。
4. **20 分钟**：写 BFS 判断两个图节点是否连通。
5. **20 分钟**：写“最近 `k` 个元素之和”，并处理 `k=0`、`k>n` 和整数范围。

每题按四项各 1 分：

- 从空白文件独立完成；
- 核心算法正确；
- 主动覆盖至少两个边界；
- 能解释不变量和复杂度。

总分解释：

- **0～7**：先完成 C++ 基础复习和 8 周路线；
- **8～13**：C++ 手感尚可，但算法模式不稳定，走 8 周或 28 天路线；
- **14～17**：走 28 天路线，按错题跳转；
- **18～20**：直接做一套基础卷和一套未读过答案的追加卷，以真实错误决定复习重点。

诊断不是为了给自己贴标签，而是防止把时间花在已经掌握或完全跳级的内容上。

## 3. 每天固定训练循环

推荐每天 2～3 小时，拆成四段：

1. **回忆 20 分钟**：不看答案重写昨天一道题的伪代码和不变量；
2. **学习 40 分钟**：读一个新模式，只选 1～2 道完整母题；
3. **空白实现 60 分钟**：关掉答案写 C++，补定向测试；
4. **复盘 20 分钟**：记录最小反例、错误类别和下次重写日期。

时间更多时，优先增加“空白实现和追问”，不要连续看更多题解。

每题采用固定动作：

```text
复述题意
→ 写约束和边界
→ 手算两个样例
→ 给最直接正确解
→ 找瓶颈与不变量
→ 写伪代码
→ 说明正确性和复杂度
→ 写 C++20
→ 跑定向测试
→ 与暴力解随机对拍（适用时）
→ 回答两个需求变化
```

## 4. 8 周完整版

适合算法基础不稳、C++ 久未使用，或希望形成可迁移能力的读者。每周学习 6 天，第 7 天只复测和休息。

### 第 0 周：恢复 C++ 与工具

阅读：

- [C++ 基础复习](../cpp/basics_refresher.md)；
- [指针、引用与 const](../cpp/pointers_references.md)；
- [STL（C++ 标准模板库）容器与成本模型](../cpp/stl_cost_model.md)；
- [C++ 解题工具箱](cpp_toolbox.md)；
- [在线笔试输入输出](online_judge_io.md)。

交付物：

- 能独立写 `vector`、`string`、`unordered_map`、`map`、`set`、`queue`、`deque`、`priority_queue` 的最小程序；
- 会写 lambda 比较器；
- 能解释 `size_t`、有符号整数、迭代器失效与整数溢出；
- 建好一条本地编译命令和 Sanitizer（运行期内存/未定义行为检查工具）命令；
- 能从标准输入读到 EOF（文件结束）、处理多组测试，并按题目要求精确输出。

### 第 1 周：解题流程、复杂度、数组与字符串

阅读：[从题目到算法](problem_solving.md)、[复杂度与正确性](complexity_correctness.md)、[数组与字符串](arrays_strings.md)。

核心模式：

- 线性扫描与维护状态；
- 双指针；
- 固定/可变滑动窗口；
- 前缀和与差分；
- 原地修改与输出位置。

周末验收：从空白实现“移除重复”“最长满足条件窗口”“区间和查询”各一题，并为优化版写暴力对拍。

### 第 2 周：哈希、排序、二分、区间与字符串解析

阅读：[哈希、排序与二分](hashing_binary_search.md)、[排序、划分与选择](sorting_selection.md)、[字符串算法](string_algorithms.md)。

核心模式：

- 频次和“是否见过”；
- 排序后相邻关系；
- 使用标准库排序、写合法比较器，并理解第 `k` 个元素的不同求法；
- 区间合并与扫描线；
- 精确查找、lower bound、`first true`；
- 对答案二分；
- 字节串扫描和精确字段解析；KMP（线性字符串匹配算法）、滚动哈希仅在岗位或模拟要求时选学。

周末验收：不背模板，能从闭区间/半开区间不变量推导二分边界；能构造一个 `mid` 计算或循环条件错误的最小反例。

### 第 3 周：栈、队列、堆与链表

阅读：[栈、队列与堆](stack_queue_heap.md)、[链表与树](linked_list_tree.md)前半。

核心模式：

- 括号与普通栈；完整表达式求值器属于 P2，不占用首轮训练时间；
- 单调栈、单调队列与摊还分析；
- Top-K、多路合并与最小堆；
- 链表反转、合并、快慢指针和判环。

周末验收：画出每次入栈/出栈；链表题先在纸上画指针变化，再写代码；能说明为什么保存 `next` 后才能改链。

### 第 4 周：树、图、递归与回溯

阅读：[链表与树](linked_list_tree.md)后半、[图与搜索](graph_search.md)。

核心模式：

- DFS/BFS 与 visited；
- 前序、中序、后序和层序；
- 递归返回值、基础树遍历与二叉搜索树（BST）边界；
- 拓扑排序；并查集和 Dijkstra 作为 P1 二选一或按岗位补充；
- 回溯中的选择与撤销作为 P1，不要求首轮掌握复杂剪枝。

周末验收：同一棵树分别写递归 DFS 和迭代 BFS；为有向图写拓扑排序并返回是否有环；解释 BFS 最短路成立需要“边权相等”这一前提。

### 第 5 周：贪心与基础动态规划

阅读：[贪心与动态规划](greedy_dp.md)、[动态规划模式](dp_patterns.md)。

核心模式：

- 贪心选择与交换论证；
- 为错误贪心构造反例；
- DP 状态、转移、初始化和遍历顺序；
- 先掌握一个一维 DP 和一个简单网格/二维 DP；
- 背包、最长递增子序列（LIS）与答案恢复按薄弱点选择，区间 DP 属于 P2；
- 用小规模暴力解验证状态定义和转移。

周末验收：拿到 DP 题时先写“`dp[state]` 表示什么”，再写转移；能够说明空间压缩后为什么可能无法直接恢复路径。

### 第 6 周：流式、缓存、调度与岗位补强

阅读：[流式与工程算法](streaming_systems.md)、[位运算与数学](bit_math.md)、[进阶数据结构](advanced_structures.md)、[岗位场景综合题](company_scenarios.md)。

核心模式：

- 滚动统计和对拍；
- 序号缺口、重复与过期；
- LRU（淘汰最久未使用项的缓存）、限流、任务 DAG（有向无环依赖图）；
- 多路流合并、简化订单簿和风险 Top-K；
- 位图/位掩码和整数边界；数论、Fenwick 树与线段树只在岗位明确要求时选学。

周末验收：任选一个通用题，分别包装成基础设施语境和 HFT 语境；指出算法模型距离生产系统还缺少哪些语义。不要把“读完进阶结构章”当作本周交付物。

### 第 7 周：限时模拟与岗位补强

先从[基础模拟笔试](mock_exams.md)选择一套，再从[追加盲测](mock_exams_extra.md)选择一套未看答案的卷，并用[能力覆盖矩阵](coverage_matrix.md)查漏。只有失分模式需要重做，不要求为了打卡完成全部卷：

- 第 1 天做基础卷 A，立即复盘；
- 第 3 天从空白重做错题；
- 第 4 天只修复覆盖矩阵中暴露的两类错误，并各做一个陌生变体；
- 第 5 天从追加卷 C/D 中抽一套盲测；D2 的 KMP 只计入字符串专项岗位；
- 第 6 天进行 45 分钟模拟面试；
- 第 7 天把覆盖矩阵中的空格变成下一轮训练清单。

岗位补强不要平均用力：

- Agent Infra（模型/智能体基础设施）或服务端：图、缓存、区间、限流、流式处理之外，还要补 Linux、网络、存储、并发与系统设计；
- 搜索/训练框架/高性能方向：堆、Top-K、图、数值边界之外，还要补 C++ 性能、并行、GPU/通信或检索；
- 量化实现/HFT 开发：窗口、堆、有序结构、序号和订单簿之外，还要补 C++ 生命周期、并发、网络与市场微观结构；
- 量化研究/AI 算法：通用 DSA（Data Structures and Algorithms，数据结构与算法）之外，还要按岗位补概率统计、线性代数、优化、机器学习与研究讨论。

## 7. 间隔重写：第 0、2、7、21 天

一道题第一次做对，可能只是短期记忆。建议安排：

- **第 0 天**：看完讲解后关掉答案，写出完整代码；
- **第 2 天**：只看题目重写，要求说出不变量；
- **第 7 天**：限时重写一个变体；
- **第 21 天**：放进混合模拟，不提示所属模式。

若第 7 天仍要逐行回忆原代码，说明你记住了文本，没有掌握结构。此时换变量名、输入形式或业务包装再做。

## 8. 错题不是按题名分类

使用六类错误：

| 类型 | 典型表现 | 修复动作 |
|---|---|---|
| 约束理解 | 漏看有序、重复、负数或无解 | 先复述输入输出，手写约束表 |
| 不变量 | 会背模板，改一点就错 | 每轮循环前后写一句状态含义 |
| 复杂度 | 嵌套循环一律说 `O(n²)` | 统计每个元素一生进入/离开次数 |
| C++ API | 比较器反了、引用失效 | 写 10 行最小程序验证接口 |
| 边界 | 空、单元素、极值失败 | 固定边界清单 + 最小反例 |
| 表达 | 代码能写，讲不清为什么 | 录音做 30 秒、2 分钟两版解释 |

每周只选出现最多的两类错误重点修复。一次改变六件事，通常什么也没有真正改变。

## 9. C++ 笔试固定检查清单

提交前用最后 3～5 分钟逐项检查：

- [ ] `#include` 是否完整，函数签名是否符合题目？
- [ ] 空输入、`k=0`、无解和重复值是否有明确行为？
- [ ] 下标是元素位置还是数量？`end` 是否为尾后位置？
- [ ] 有符号与无符号比较是否安全？
- [ ] 乘法/加法是否在扩大类型或检查溢出之前就已经发生？
- [ ] `priority_queue` 默认最大堆，比较器方向是否正确？
- [ ] `sort` 的比较器是否满足严格弱序，是否处理并列？
- [ ] 保存的指针、引用或迭代器是否可能因容器修改失效？
- [ ] 递归深度是否可能超过栈限制？
- [ ] BFS 入队时还是出队时标记 visited？是否造成重复入队？
- [ ] 二分循环每步是否严格缩小区间？
- [ ] 返回值顺序是否确定，隐藏测试会不会要求 tie-breaker？

## 10. 面试表达模板

拿到题后可以这样开场：

> 我先确认输入规模、是否有序、是否允许重复，以及无解时返回什么。然后我会先给一个容易验证的基线，再看约束是否要求优化。实现时我会保持一个明确不变量，最后覆盖空输入、单元素、重复和极值。

找到算法后，不要沉默写到底。每完成一段说一句：

- “这个哈希表保存已经看过的值到下标，因此当前元素到来时能检查互补值。”
- “这个窗口始终满足条件；右端扩张，失效时移动左端恢复条件。”
- “堆中只有每一路尚未输出的头部，因此全局最小值一定在堆里。”
- “`dp[i]` 表示前 `i` 个元素的最优答案，初始化对应空前缀。”

这些话既帮助面试官理解，也会迫使你检查自己的逻辑。

## 11. 岗位材料怎样反向调整计划

每次收到面试邀请后重新读岗位说明，不把所有岗位混为一谈：

1. 标出明确语言：C++、Rust、Python 或不限定；
2. 标出算法、系统、数学、模型、业务的关键词；
3. 询问招聘方允许的语言、笔试平台和大致形式；
4. 把计划中 20%～30% 时间调整到岗位特定内容；
5. 不依据匿名经验帖断言“必考”，只把它当练习线索。

通用算法是地基，不是全部房子。尤其 DeepSeek 的系统岗位和九坤的低延迟岗位，算法题之后仍可能深入操作系统、网络、并发、C++ 生命周期、性能证据、概率统计或项目经历。

## 12. 最终就绪门槛

满足下面条件再把自己评为“算法轮准备较充分”：

- [ ] 诊断题达到 18/20，且一周后仍能达到；
