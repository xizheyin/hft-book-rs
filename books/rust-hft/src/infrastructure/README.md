# 并发与通用基础设施

这一部分研究多个执行单元怎样安全交换数据，以及一个服务怎样在负载增长和故障发生时保持边界清楚。内容分成三层：并发原语负责正确交接状态，队列与背压负责限制在途工作，日志、配置和指标负责让系统可以操作和诊断。

```mermaid
flowchart LR
    A["原子操作与同步"] --> B["队列与所有权交接"]
    B --> C["批处理、流水线与背压"]
    C --> D["分片与容量扩展"]
    D --> E["日志、配置与指标"]
```

## 并发原语与队列

| 问题 | 主讲章节 | 核心内容 |
|---|---|---|
| 一个线程怎样发布状态，另一个线程何时能看见 | [原子操作](atomics.md) | 原子性、内存顺序、Acquire/Release |
| 不使用互斥锁的数据结构怎样保证整体取得进展 | [无锁数据结构](lock_free.md) | CAS、进展保证、ABA 与安全回收 |
| 固定容量的循环存储怎样复用槽位 | [Ring Buffer](ring_buffer.md) | head/tail、回绕、满空判断与所有权 |
| 生产者和消费者数量怎样改变队列协议 | [队列拓扑](queues.md) | SPSC、MPSC、SPMC、MPMC、有界与无界 |

原子内存顺序只由原子操作章完整解释；队列和日志章节使用结论并链接回去，不重复维护第二套证明。

## 可运行与可诊断

| 问题 | 主讲章节 | 核心内容 |
|---|---|---|
| 程序怎样记录可恢复、可查询的事件 | [日志系统](logging.md) | 事件格式、缓冲、落盘、丢弃与故障边界 |
| 新配置怎样一次性替换旧配置 | [配置热更新](config.md) | 解析、验证、一致快照、发布、回滚与审计 |
| 怎样知道系统正在发生什么 | [指标与遥测](metrics.md) | counter、gauge、histogram、标签与观测成本 |

有界队列、背压、配置一致性和可观测性是传统后端、AI 基础设施与交易系统都会使用的通用机制。无锁容器、非一致内存访问（Non-Uniform Memory Access，NUMA）布局和特定硬件优化建立在这些机制之上，只有经过负载测量和并发证明，才能判断它们是否适合具体系统。
