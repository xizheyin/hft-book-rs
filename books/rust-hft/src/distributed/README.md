# 分布式系统基础

分布式系统把一次业务操作拆到多台独立机器上。机器可以单独崩溃，网络会延迟或丢包，各节点也没有完全一致的时钟，因此“调用成功了吗”“哪个值更新”“谁是当前主节点”都需要协议回答。

复制解决“同一份数据保存多份”，分片解决“不同数据分到多处”，共识解决“多个节点对一个不可撤销决定达成一致”，事务与幂等解决“跨步骤失败时业务结果仍可解释”。这些概念会组合使用，但不能互相替代。

一次远程写入至少经过“客户端发送—服务端执行—服务端回复”三个阶段。客户端超时时，请求可能没有到达，也可能已经提交但回复丢失，因此 timeout 只能说明“没有及时观察到结果”；稳定幂等键、持久化去重和状态查询共同把这种未知结果变成可安全恢复的流程。

数据复制以后，节点故障不等于数据立即丢失，但读到哪个版本取决于确认点和一致性协议；数据分片以后，总容量可以增加，但不带分片键的查询可能必须访问所有分片。系统设计必须先说明接口承诺，再选择复制、共识、分片、缓存和事务机制。

网络分区期间，无法通信的两侧不能同时知道对方刚刚接受了什么写入；继续让两侧都成功响应会产生冲突，等待或拒绝其中一侧则会降低可用性。这一矛盾是理解 CAP、选主和脑裂防护的共同起点。
