# C++ 量化与 HFT 面试学习路线

C++ 很大，零基础读者最容易犯的错误是从语法大全第一页开始背，几周后仍不知道面试为什么问对象生命周期和缓存。本章给出一条以低延迟系统为目标的路线：每一步都有可交付成果，而不是只规定“看多少页”。

> **本章目标**：根据目标岗位选择学习深度，安排六周练习，并用“能解释、能写、能验证”判断自己是否真正掌握。

## 1. 先确认岗位，不要把所有量化岗位混在一起

| 岗位方向 | C++ 学习重点 | 还要补什么 |
|---|---|---|
| 交易系统/低延迟开发 | 生命周期、内存、并发、网络、性能工具 | Linux、CPU、协议、系统设计 |
| 量化实现/Quant Developer | 可靠编码、数据结构、性能意识 | 数学、统计、Python、研究协作 |
| 量化研究 | 能实现和验证研究代码，C++ 深度因团队而异 | 概率统计、优化、机器学习、实验方法 |
| Linux 内核/基础设施 | C/C++、并发、系统调用、硬件边界 | 内核、驱动、网络、故障诊断 |

如果招聘说明或面试邀请明确指定语言，以那份信息为准。本书的路线主要服务前两类岗位。

## 2. 开始前只准备最小工具箱

你需要一台可以运行 GCC 或 Clang 的 Linux/macOS 机器，以及下面四个动作：

```bash
c++ --version
c++ -std=c++20 -Wall -Wextra -Wpedantic hello.cpp -o hello
./hello
c++ -std=c++20 -fsanitize=address,undefined -g hello.cpp -o hello_san
```

此时不用先学会复杂 CMake。先能完成“编辑 → 编译 → 运行 → 看懂第一条错误信息”的闭环。

## 3. 六周主线

每天建议 60–90 分钟。如果时间更少，延长周数，不要跳过练习。

### 第 1 周：知道代码怎样变成程序

阅读：[基础复习：重新找回手感](basics_refresher.md)、[编译与内存](compilation_memory.md)、[指针与引用](pointers_references.md)。如果基础复习中的语法已经完全陌生，先把[最小语法与数据建模](minimal_syntax.md)当作详细教材补读。

你要完成：

- 把声明和实现放进两个文件并成功链接；
- 画出一个局部变量、一个动态对象和一个引用的关系；
- 能解释“指针可以为空，引用通常表示已有对象的别名”；
- 用编译器警告修正一次类型转换问题。

**周末产出**：不看书解释预处理、编译、链接分别在做什么。

### 第 2 周：掌握对象生命周期

阅读：[RAII](raii_lifetime.md)、[拷贝与移动](copy_move.md)、[智能指针](smart_pointers.md)。

你要完成：

- 写一个构造时获取资源、析构时释放资源的小类；
- 观察拷贝和移动分别调用哪个函数；
- 用 `std::unique_ptr` 表达独占所有权；
- 能说明为什么 `std::shared_ptr` 不是默认选择。

**周末产出**：回答“返回局部对象为什么可以安全”“什么是悬空引用”。

### 第 3 周：建立成本模型

阅读：[STL 成本模型](stl_cost_model.md)、[模板与多态](templates_polymorphism.md)、[内存布局](memory_layout.md)。

你要完成：

- 比较 `vector`、`deque`、`map` 的存储方式和复杂度；
- 写一个受 Concept 约束的函数模板；
- 解释虚函数、模板静态分发的主要权衡；
- 用 `sizeof`、`alignof` 观察字段顺序带来的布局变化。

**周末产出**：给订单簿选择容器，并主动说明未知条件和验证方案。

### 第 4 周：理解并发正确性

阅读：[错误、异常与未定义行为](errors_ub.md)、[原子与内存模型](atomics_memory_model.md)、[无锁结构](lock_free.md)。

你要完成：

- 区分原子性、可见性和顺序；
- 解释数据竞争为什么属于未定义行为；
- 在纸上推演 SPSC 队列的空、满和回绕；
- 知道 `memory_order_relaxed` 只保证什么、不保证什么。

**周末产出**：用一句话和一个时序解释 Release/Acquire 发布数据。

### 第 5 周：学会证明，而不是猜快慢

阅读：[分配器与零拷贝](allocators_zero_copy.md)、[优化和工具链](optimization_tooling.md)。

你要完成：

- 建立一个包含预热和 `DoNotOptimize` 等价屏障思想的微基准；
- 分别运行 ASan、UBSan、TSan 的适用示例；
- 用 `perf stat` 或平台工具观察缓存和分支指标；
- 记录硬件、编译器、flags、负载和 P50/P99。

**周末产出**：写一页性能实验报告，哪怕结果是“没有显著改善”。

### 第 6 周：串起 HFT 链路

阅读：[C++ HFT 贯穿项目](hft_capstone.md)，再回看[订单簿](../engine/order_book.md)、[风控](../engine/risk.md)和[网络基础](../network/basics.md)。

你要完成：

- 画出行情到订单回报的数据流；
- 给程序增加行情序号和 Gap 状态；
- 给风险检查加入未成交订单预占；
- 做一次 45 分钟模拟面试并复盘。

**周末产出**：一个能编译、有测试、有 README、有测量记录的小项目。

## 4. 每个知识点用三层标准验收

| 层次 | 你能做什么 | 以移动语义为例 |
|---|---|---|
| 解释 | 用自己的话说明目的 | 移动用于转移可转移资源，避免不必要的深拷贝 |
| 编写 | 写出边界清楚的代码 | 类型满足 Rule of Zero，调用处使用值返回和 `unique_ptr` |
| 验证 | 用工具检查真实行为 | 看构造日志、测试 moved-from 状态，并由基准判断是否有收益 |

只会复述“`std::move` 会移动”还不够。`std::move` 本身只是类型转换，最终是否转移资源取决于被调用类型的移动操作。

## 5. 高频主题优先级

### 第一优先级：必须能讲清

- 栈、堆、对象生命周期与 RAII；
- 指针、引用、`const`、悬空与空指针；
- 拷贝、移动、`unique_ptr`、`shared_ptr`；
- `vector` 扩容与迭代器失效；
- 数据竞争、原子、Acquire/Release；
- 缓存行、false sharing、内存布局；
- 未定义行为和 Sanitizer；
- 延迟分位数、基准边界和性能证据。

### 第二优先级：开发岗常追问

- 模板、Concepts、`constexpr`、CRTP；
- 虚函数与静态分发；
- allocator、Arena、对象池；
- SPSC/Ring Buffer 的不变量；
- 编译优化、LTO、PGO 和生成汇编；
- TCP/UDP、字节序、协议解析和系统调用。

### 第三优先级：按岗位深入

- DPDK、AF_XDP、OpenOnload；
- NUMA、跨核通信和硬件时间戳；
- SIMD intrinsics；
- FPGA、内核或网卡驱动；
- 跨语言 LTO 与复杂 ABI。

## 6. 白板编码时的固定顺序

拿到“实现一个队列/订单簿/解析器”时，可以按下面顺序说：

1. 先确认输入、输出、容量和并发模型；
2. 写出不变量和失败语义；
3. 选择最简单正确的数据结构；
4. 处理空、满、越界、溢出和重复输入；
5. 写最小测试；
6. 最后讨论怎样优化以及如何证明。

这个顺序能避免一上来就写无锁代码，却没有说明生产者数量和队列满时怎么办。

## 7. 常见面试追问

### Q1：`unique_ptr` 和 `shared_ptr` 怎么选？

**参考骨架**：默认先寻找单一所有者，用 `unique_ptr` 或直接值成员表达；确实存在跨组件共享生命周期时才考虑 `shared_ptr`。后者有控制块、引用计数和更复杂的销毁时机，还要处理循环引用。是否影响热路径要测量，不能只背“原子计数很慢”。

### Q2：`vector` 扩容会发生什么？

**参考骨架**：需要更大连续空间时，它会申请新存储，把现有元素移动或拷贝过去，再释放旧存储；一旦发生重新分配，指向旧元素的指针、引用和迭代器全部失效。可以根据上界 `reserve`，但不能凭感觉预留巨大空间。

### Q3：无锁一定比锁快吗？

**参考骨架**：不一定。无锁结构减少某些阻塞风险，但增加原子、缓存一致性、回收和验证复杂度。先明确线程拓扑与进度保证，再用目标负载比较尾延迟和吞吐。

### Q4：怎样证明一次优化没有改错业务？

**参考骨架**：固定输入回放，对比优化前后的输出、状态哈希和业务不变量；再在相同硬件和构建条件下比较延迟分布。正确性证据与性能证据缺一不可。

## 8. 新手最常见的无效学习方式

- 背几百道语法题，却从没用编译器和 Sanitizer；
- 看到裸指针就说错误，或看到智能指针就说安全；
- 只写成功路径，不定义队列满、行情断档和撤单竞态；
- 把平均延迟当成尾延迟；
- 把 `-O3`、无锁或内联当成自动性能保证；
- 一开始就读复杂生产级开源代码，无法分辨业务逻辑和优化细节。

## 9. 自测清单

面试前，逐项确认自己可以不看书回答：

- [ ] 一个 `.cpp` 文件怎样经过编译和链接变成程序？
- [ ] 对象、指针、引用和所有权有什么区别？
- [ ] RAII 如何处理提前返回和异常路径？
- [ ] 拷贝、移动和 `std::move` 分别是什么？
- [ ] 哪些操作会让 `vector` 的引用失效？
- [ ] 数据竞争为什么不是“偶尔读错一次”那么简单？
- [ ] Acquire/Release 保护的是哪段数据发布关系？
- [ ] SPSC 队列的生产者和消费者分别写哪些索引？
- [ ] false sharing 为什么发生在不同变量之间？
- [ ] 怎样用 Sanitizer、回放和基准形成证据链？

任何一项只能回答名词时，就回到对应章节完成一个小实验，不要继续堆新名词。

## 10. 练习与参考答案

### 练习 1

你只有两周时间，目标是交易系统开发面试。应该先学模板元编程还是生命周期和并发？

<details>
<summary>参考答案</summary>

先补生命周期、RAII、容器失效、数据竞争和原子内存序。这些既是正确性基础，也更容易被系统开发面试连续追问。模板先掌握函数/类模板、Concepts 和静态分发的基本权衡，再按岗位扩展复杂技巧。

</details>

### 练习 2

一个微基准显示新实现平均快 15%，能否宣布优化成功？

<details>
<summary>参考答案</summary>

不能。还需确认输入和输出语义一致，记录硬件、构建、预热、样本与计时边界，并查看 P50/P99/P99.9、吞吐和资源变化。还要排除编译器删掉工作、缓存状态不同或样本不代表生产负载等问题。

</details>

## 小结

- 按岗位决定 C++ 深度，不把研究、实现和系统开发混为一谈；
- 学习顺序是编译与生命周期 → 成本模型 → 并发 → 性能验证 → HFT 项目；
- 每个主题都要达到“能解释、能写、能验证”；
- 面试中的高质量答案应包含结论、原因、权衡和验证方法。
