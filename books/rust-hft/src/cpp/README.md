# 现代 C++：从对象生命周期到系统开发

C++ 既能写普通业务程序，也能直接管理内存、线程和机器资源。数据库、浏览器、AI 推理运行时、基础设施和交易系统都会使用它，因为工程师可以明确控制对象放在哪里、何时创建和销毁，以及接口是否发生复制和分配。

这部分以 **C++20** 为基线，从第一段最小语法和亲手编译程序讲起，再进入对象生命周期、模板、并发和性能工程。

## 先看全局：一段 C++ 程序怎样跑起来

```mermaid
flowchart LR
    A[源代码 .cpp] --> B[编译器检查并翻译]
    B --> C[目标文件 .o]
    C --> D[链接器组合库和目标文件]
    D --> E[可执行文件]
    E --> F[操作系统启动进程]
```

初学时最容易把三个问题混在一起：

- **语法是否正确**：由编译器先检查；
- **函数是否真的有实现**：通常在链接时确认；
- **程序运行是否符合预期**：只有运行、测试和观测才能回答。

“编译成功”只说明程序满足了一部分静态规则，并不说明它没有越界、悬空引用、数据竞争或业务错误。现代 C++ 提供了 RAII、标准容器和智能指针来减少这类风险，但仍需要程序员主动建立清楚的不变量。

## 核心语言语义怎样关联

C++ 的资源管理建立在对象生命周期上，并发正确性又建立在对象仍然有效、没有数据竞争的前提上。各主题有下面的依赖关系：

1. **[编译、链接与内存直觉](compilation_memory.md)**：知道代码如何变成程序，区分自动存储期、动态存储期和静态存储期。
2. **[指针、引用与 `const`](pointers_references.md)**：知道“对象”和“对象的地址”不是一回事，能表达可空与不可空的借用。
3. **[RAII 与生命周期](raii_lifetime.md)**：让资源跟着对象自动释放，理解构造和析构。
4. **[复制与移动](copy_move.md)**：看懂对象为什么有时被复制、有时转移资源，以及 `std::move` 到底做了什么。
5. **[智能指针](smart_pointers.md)**：用类型表达独占、共享和弱观察关系。
6. **[STL 成本模型](stl_cost_model.md)**：会使用 `vector`、`array`、`string`、映射和算法，同时知道分配、扩容与缓存局部性。

模板与多态决定具体实现是在编译期还是运行时选择；内存布局说明对象怎样排列；错误与未定义行为划定语言保证的边界；原子内存模型和无锁结构建立在对象生命周期与无数据竞争的前提上。分配器、零拷贝与优化工具用于观察和改变实际成本。[C++ HFT 贯穿项目](hft_capstone.md)展示这些语义怎样在一个完整业务流程中组合。

## C++ 与 Rust：先建立一座桥

如果你读过本书的 Rust 部分，可以暂时用下表建立映射。它只是一张导航图，不表示两种语言完全等价。

| 想表达的事 | Rust 常见写法 | C++ 常见写法 | 关键差异 |
|---|---|---|---|
| 局部拥有值 | `let x: T = value;` | `T x{value};` | 都通常随作用域结束生命周期；优化器可能改变实际存储位置 |
| 只读借用 | `&T` | `const T&` | C++ 编译器不做完整的借用检查 |
| 可变借用 | `&mut T` | `T&` | C++ 不保证同一时间只有一个可变引用 |
| 独占堆所有权 | `Box<T>` | `std::unique_ptr<T>` | 都适合表达唯一所有者 |
| 共享所有权 | `Arc<T>` | `std::shared_ptr<T>` | 计数/控制块可安全共享不等于 `T` 自动线程安全；内容仍需满足各自约束 |
| 可选值 | `Option<T>` | `std::optional<T>` | C++ 指针也可用 `nullptr` 表示“没有对象” |
| 析构清理 | `Drop` | 析构函数 / RAII | C++ 析构时机还会受所有权写法影响 |
| 移动 | 默认按 Rust 所有权规则 | 移动构造/赋值 | C++ 被移动对象通常仍存在，但状态可能改变 |

最重要的区别可以先记成一句话：

> Rust 尝试让编译器证明借用关系；C++ 给程序员更多表达自由，也把更多生命周期证明责任交给程序员。

## 贯穿案例：一条简化行情

这部分会反复使用一个很小的教学对象：

```cpp
#include <cstdint>
#include <iostream>

struct Quote {
    std::int64_t price_ticks;
    std::uint32_t quantity;
};

int main() {
    const Quote best_bid{10'025, 300};
    std::cout << "best bid: " << best_bid.price_ticks
              << " ticks, quantity: " << best_bid.quantity << '\n';
}
```

把价格写成整数 `price_ticks`，意思是“多少个最小变动单位”，而不是直接使用浮点数。例如最小变动单位为 0.01 元时，`10'025` ticks 表示 100.25 元。整数单位让示例更容易讨论溢出、布局和确定性，但真实市场的价格表示仍应以接入场所的协议为准。

代码中的单引号只是数字分隔符：`10'025` 与 `10025` 完全相同，前者更容易阅读。

## 怎样运行本部分的示例

带 `cpp` 标记的代码块都是一个完整源文件，且各自只有一个 `main`。保存为 `main.cpp` 后可使用支持 C++20 的编译器：

```bash
c++ -std=c++20 -Wall -Wextra -Wpedantic main.cpp -o demo
./demo
```

标记为 `cpp,ignore` 的代码块是局部片段、伪代码或故意展示的错误，正文会说明它为什么不能直接编译。不要把“警告为零”当成程序正确的证明；警告、静态分析、测试、Sanitizer（动态错误检查工具）和基准测试回答的是不同问题。

## 贯穿全书的成本问题

看到任何 C++ 抽象时，都可以先问五个问题：

1. 对象的数据放在哪里？
2. 谁拥有它，谁只是临时查看它？
3. 它何时被销毁，引用能否活得更久？
4. 这一步是否分配、复制、加锁或做间接跳转？
5. 这些成本是否真的发生在被测量为瓶颈的热路径？

这五个问题比背诵“某个类型快、某个类型慢”更可靠。低延迟优化不是把所有高级抽象删除，而是让关键路径上的资源和控制流更可预测，并用真实负载验证。

## 小结

C++ 学习的主线不是记语法，而是理解对象、生命周期和成本。先用现代类型建立清晰所有权，再逐步学习底层机制；这样既能写出能工作的程序，也能解释它在机器上为什么这样工作。
