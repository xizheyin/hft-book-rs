# 前言：这本书解决什么问题

HFT（高频交易）面试难，不是因为它只考一个特别深的知识点，而是因为面试官会把市场规则、Rust 或 C++、操作系统、网络、并发和性能测量连在一起追问。只背术语时，你也许能回答第一问，却很难解释“为什么这样设计”“出错后怎样恢复”“怎样证明真的更快”。

本书要解决的核心问题，是帮你把这些分散知识连成一条可以推演的工程链路。你不需要预先懂金融或低延迟系统；每个重要概念都会先给直觉和小例子，再进入准确术语、实现边界和面试表达。

## 面试真正检查的三层能力

| 层次 | 面试官可能怎样问 | 你需要展示什么 |
|---|---|---|
| 事实 | 限价单是什么？`Acquire` 有什么作用？ | 能准确说明定义、适用范围和前提 |
| 推理 | 行情丢包后为什么不能继续交易？ | 能沿数据、状态和风险约束推导后果 |
| 设计 | 怎样把交易链路做到低延迟且可恢复？ | 能给出方案、权衡、验证方法和降级路径 |

因此，本书不会把“用了无锁队列”“线程绑核”“Rust 没有 GC”当成答案终点。一个高质量回答还要说明组件之间的所有权、队列满时怎么办、内存顺序保护了什么、测量边界在哪里，以及优化是否破坏了业务正确性。

## 本书怎样组织知识

```mermaid
flowchart LR
    A[市场与订单] --> B[行情和交易链路]
    B --> C[正确性与风险约束]
    C --> D[Rust/C++ 与系统实现]
    D --> E[延迟和吞吐优化]
    E --> F[测试、回放与证据]
    F --> G[系统设计与面试表达]
```

前半段先回答系统“为什么存在”和“什么算正确”，后半段再回答“怎样实现”和“怎样优化”。这种顺序很重要：如果订单状态、行情序号或风险限额本来就是错的，再快的代码也没有价值。

## 你与本书的学习约定

- 第一次看到缩写时，先理解它解决的问题，不急着背英文全称。
- 遇到图和算例时，亲手推演一次；能看懂不等于能独立回答。
- 遇到代码时，先找不变量、输入边界和失败路径，再看语法细节。
- 遇到性能结论时，主动追问硬件、负载、样本、分位数和计时范围。
- 每学完一章，用“结论—原因—权衡—验证”四步法复述给自己听。

## 内容边界

本书讨论工程方法和面试知识，不提供交易策略，不承诺收益，也不替代交易所规则、监管要求或生产系统审计。不同市场的撮合、订单和风控规则可能不同；真正实现前必须核对目标场所的最新官方规范。
