# 如何使用本书：从零基础到面试表达

这不是一本需要从第一页背到最后一页的词典。更有效的方法是：先建立地图，再沿一条真实交易链路补知识，最后用面试题检查能否把知识讲出来。

## 先做 10 分钟自测

不要查资料，尝试口头回答下面五题。答不完整很正常，它们只是帮你选择起点。

1. 买一价 100 元有 30 手，新的 40 手市价买单会发生什么？
2. 行情序号从 100 跳到 102，本地订单簿还能继续用于交易吗？
3. “平均延迟 5 微秒，P99 50 微秒”说明了什么？
4. 为什么两个线程修改两个不同变量，仍可能因为缓存行而互相拖慢？
5. 盘前风控为什么不能只在策略里写一个 `if`？

| 能完整回答的数量 | 建议起点 |
|---:|---|
| 0–1 | 从 HFT 总览开始，先补市场和交易链路 |
| 2–3 | 从市场微观结构开始，同时阅读订单簿与风控 |
| 4–5 | 先做高频题库和系统设计题，用错题反向学习 |

## 再选择一条语言路线

HFT 原理、订单状态和风控约束与语言无关，但面试编码会落到具体语言。第一次学习时先选一条主路线，另一种语言通过对照框建立映射，不必同时背两套语法。

| 你的情况 | 推荐入口 |
|---|---|
| 没学过 C++，目标是量化实现或低延迟开发 | 从 [C++ 部分导论](../cpp/) 开始，再跟随 [六周路线](../cpp/interview_roadmap.md) |
| 以前写过 C++，但已经忘得差不多 | 先做 [C++ 基础复习](../cpp/basics_refresher.md)中的 30～90 分钟诊断，再按错题回查详细章节 |
| 已有 C++ 基础，想理解 Rust 安全模型 | 从所有权与生命周期开始，再读 C++ 迁移指南 |
| 已有 Rust 基础，目标岗位使用 C++ | 重点比较 RAII、移动语义、容器失效、UB 和 C++ 原子内存模型 |
| 暂时只学 HFT 业务 | 先读第一部分；遇到实现问题再回到对应语言章节 |

## 一个概念要学到哪一层

面试中的“会”至少分四层：

| 层级 | 你能做到什么 | 以 SPSC 队列为例 |
|---|---|---|
| 识别 | 见过名词 | 知道它是单生产者、单消费者队列 |
| 解释 | 说清工作方式 | 能解释 head/tail 和环形数组 |
| 推演 | 处理边界条件 | 能说明满、空、回绕和内存顺序 |
| 权衡 | 在场景中做选择 | 能比较 SPSC、MPSC、Mutex 队列，并给验证方案 |

本书的目标是让核心主题达到第三或第四层。只到“识别”层的知识，在追问面前通常坚持不了两轮。

## 面试回答的四步骨架

遇到系统问题，可以用 **结论 → 原因 → 权衡 → 验证** 组织答案。

> **示例问题：为什么 HFT 热路径常用单线程？**
>
> **结论**：对于单个有明确顺序的状态分片，我会优先评估单写者、线程绑核的模型。
>
> **原因**：它减少锁竞争、跨核缓存一致性流量和调度抖动，并让事件顺序更容易推理。
>
> **权衡**：单核吞吐有上限；慢处理会阻塞后续事件，扩展时需要按标的或连接分片。
>
> **验证**：用目标峰值流量回放，观察 P50/P99/P99.9、队列深度、丢包和单核利用率，再决定是否需要分片。

这个骨架比“因为单线程快”强得多，因为它同时展示了原理、边界和工程方法。

## 四周学习计划

每天 60–90 分钟即可。时间更少时保持顺序，不必强行压缩理解过程。

### 第 1 周：先看懂市场

- HFT 总览与交易生命周期
- 市场微观结构
- 订单类型与撮合优先级
- 每天手工推演一个 5–10 条事件的小订单簿

**周末产出**：不看书画出“行情到成交回报”的流程图，并解释 Maker、Taker、Spread、L1/L2/L3。

### 第 2 周：看懂系统

- 市场数据、增量与快照
- 订单簿、订单路由、盘前风控、持仓
- 网络基础、UDP 组播、TCP 会话

**周末产出**：说明丢包恢复和订单状态机；完成一次 HFT 系统设计的前 20 分钟。

### 第 3 周：理解“为什么快”

- CPU、缓存、操作系统、内存布局
- 并发模型、原子操作、SPSC/Ring Buffer
- 延迟预算、CPU 亲和性、资源效率

**周末产出**：给一条 20 微秒教学链路分配预算，并列出三个最可能的尾延迟来源。

### 第 4 周：证明它正确且更快

- 基准测试、性能剖析、回放、时钟
- 单元/集成/属性/模糊测试
- 部署、降级、监控与事故处理
- 高频面试题库与系统设计模拟

**周末产出**：做一轮 45 分钟模拟面试，复盘每道题缺少的是事实、推理、边界还是表达。

## 怎样阅读代码示例

书中的代码分三类：

- **可运行示例**：展示完整 API 或算法，应在目标 Rust 版本或 C++20 编译器上验证。
- **教学片段**：只突出一个概念，可能省略错误类型、依赖和外围代码。
- **伪代码**：表达状态机或系统行为，不应直接复制进生产环境。

看到 Rust `unsafe`、C++ 裸指针或无锁代码时，请强制问四个问题：

1. 安全不变量是什么？
2. 谁负责维持它？
3. 什么输入或并发时序会破坏它？
4. 有哪些测试、Miri、fuzz 或基准证据？

如果回答不了，即使代码在基准中更快，也不应进入生产热路径。

## 怎样看性能数字

性能结论至少要记录以下上下文，否则无法复现：

| 类别 | 最低记录项 |
|---|---|
| 硬件 | CPU 型号、核心/NUMA、内存、网卡 |
| 软件 | OS、内核、Rust/LLVM 或 GCC/Clang、依赖版本 |
| 构建 | release profile、LTO、目标 CPU、PGO |
| 负载 | 消息大小、分布、批大小、并发度、预热方式 |
| 指标 | P50/P99/P99.9/max、吞吐、丢弃、CPU 与队列深度 |
| 方法 | 样本数、计时器、是否排除 I/O、噪声控制方式 |

一句“优化后快了 30%”不是证据。完整说法应该类似：“在指定硬件和峰值回放负载下，P99 从 X 降至 Y；功能回放哈希一致；代价是内存增加 Z。”

```text
正确答案的最小骨架：

```

不要复制整章。错题本的作用是让你下一次能从大脑里重建答案。

## 面试前 24 小时

- 复述交易生命周期、丢包恢复、订单状态机和风控边界。
- 手画一次系统架构，主动说出假设、容量、延迟预算和故障模式。
- 复习术语表与错题，而不是再开一个陌生专题。
- 准备两个真实项目故事：一次性能定位、一次正确性或生产事故处理。
- 对不了解的交易所细节明确说明假设，不编造规则或数字。

> **最终检查标准**
>
> 你不需要把所有技术都说成“最快”。优秀回答会指出适用条件、失败方式、替代方案和验证证据。低延迟工程不是技巧竞赛，而是受约束的系统设计。
