# 系统基础与性能模型

本部分从零建立一套共同的计算机系统基础。它不仅服务 HFT，也服务 Rust、C++、后端和 AI 基础设施面试：CPU、进程、虚拟内存、文件和网络遵循的是同一套软硬件规律，不需要在不同主题中重复学习。

阅读时始终回答三个问题：

1. **它是什么？** 先给概念在整台计算机中的位置。
2. **为什么需要它？** 说明它解决的限制、隔离或性能问题。
3. **它为什么影响当前程序？** 用一条因果链连接代码、内核、硬件和可观测证据。

## 建议阅读顺序

零基础读者不要直接从优化技巧开始。推荐顺序如下：

1. [一次程序怎样运行](computer_execution.md)
   - 先把源代码、进程、CPU、内存、内核和设备连成一张地图。
2. [进程、线程与文件描述符](processes_fds.md)
   - 理解程序怎样启动、执行系统调用、继承资源并退出。
3. [虚拟内存](virtual_memory.md)
   - 理解 VMA、页表、TLB、缺页、COW、回收和 OOM。
4. [操作系统原理](os_internals.md)
   - 把调度、中断、缺页和 I/O 放进尾延迟地图。
5. [一次文件写入](file_write_path.md)
   - 沿一次 `write` 走通页缓存、回写、设备与持久化边界。
6. [CPU 微架构](cpu_arch.md)
   - 在已有执行地图上深入流水线、Cache、分支预测和数据等待。
7. [内存布局与缓存效率](memory_layout.md)
   - 学习怎样排列数据，减少 Cache miss 和伪共享。
8. [零成本抽象](zero_cost.md)与[编译器优化](compiler_optimizations.md)
   - 理解语言抽象何时能被编译器消除，何时留下真实成本。
9. [Unsafe Rust](unsafe_rust.md)
   - 在已有内存和并发模型上学习安全边界，不把 `unsafe` 当作性能开关。
10. [并发模型](concurrency.md)与 [Async Rust](async_rust.md)
    - 比较线程、异步任务和消息传递的等待方式与适用条件。

## 每个概念由哪一章主讲

为避免同一个名词在多章出现互相冲突的解释，本部分采用“一个主讲章节，其他章节只链接”的规则：

| 问题 | 主讲章节 | 其他章节怎样使用 |
|---|---|---|
| 整台计算机的执行全景 | [一次程序怎样运行](computer_execution.md) | 只负责导航，不展开第二套细节 |
| 流水线、Cache、分支与硬件线程 | [CPU 微架构](cpu_arch.md) | OS 章节只引用它解释执行成本 |
| 进程、线程、fd、系统调用、启动与回收 | [进程与文件描述符](processes_fds.md) | 文件写入章只复用 fd 和系统调用结论 |
| VMA、页表、TLB、缺页、COW、回收、OOM | [虚拟内存](virtual_memory.md) | OS 章节只说明它们怎样形成延迟 |
| 调度、中断、亲和性与尾延迟诊断 | [操作系统原理](os_internals.md) | 不再重复虚拟内存或完整 I/O 路径 |
| `write`、页缓存、回写、设备与持久化 | [一次文件写入](file_write_path.md) | 其他章节不维护第二套写盘说明 |
| 数据布局、对齐与伪共享 | [内存布局](memory_layout.md) | CPU 和并发章节按需要链接 |
| Future、运行时与异步 I/O | [Async Rust](async_rust.md) | 通用并发章只负责方案比较 |

当一章提到陌生概念时，先沿表格回到主讲章节。这样能知道“这一段为什么突然谈它”，而不是靠猜读者已经学过。

## 学到什么深度才够面试

| 优先级 | 需要达到的程度 | 例子 |
|---|---|---|
| **P0 必会** | 能从现象讲出完整因果链，并区分相近概念 | TLB miss 与 page fault、系统调用与任务切换、`write` 与 `fsync` |
| **P1 理解** | 能比较方案的收益、代价和适用前提 | 绑核、批处理、大页、线程与异步任务 |
| **P2 岗位相关** | 目标岗位或项目明确需要时再查资料 | 某个内核版本的结构名、硬件指令参数和厂商配置 |

P2 不是没有价值，而是不应挤占基础学习时间。面试官继续追问时，优先说明“这一层解决什么问题、会增加什么成本、怎样在目标机器验证”，而不是背函数名或固定纳秒数。

## 学完后的回答标准

完成本部分后，你应该能在白板上画出：

```text
源代码 → 可执行文件 → 进程/线程 → CPU 与内存
                         ↓ 系统调用
                    Linux 内核
                         ↓
               文件系统/网络栈/驱动 → 设备
```

你还应该能把“程序慢”拆成计算、地址翻译、调度、同步或 I/O 等不同假设，并为每个假设给出一项证据。做到这一点之后，再进入 HFT 网络、交易引擎和性能工程章节，底层概念才不会变成孤立名词。
