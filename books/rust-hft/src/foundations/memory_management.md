# 内存管理：分配、换页与抖动

CPU 只能直接执行内存中的指令并访问内存中的数据，但物理内存容量有限。操作系统的内存管理必须同时回答：哪段内存属于谁、怎样保护它、空闲空间怎样分配，以及内存装不下所有活跃页面时先移走谁。

本章讲分配与置换策略。虚拟地址怎样经页表和 TLB 找到物理页、缺页怎样处理，见[虚拟内存](virtual_memory.md)。

## 1. 地址绑定发生在哪个阶段

源代码中的变量名最终要对应内存地址。这个对应关系可以在不同阶段确定：

- **编译时**：若装入位置已知，编译器可以生成固定地址；位置改变通常要重新编译；
- **装入时**：编译器生成可重定位代码，装载器在程序放入内存时决定地址；
- **运行时**：程序使用虚拟地址，硬件在每次访问时动态翻译，进程运行期间也能移动底层物理页。

现代通用操作系统主要依靠运行时地址翻译。程序看到的逻辑/虚拟地址与 RAM 的物理地址因此可以不同。

## 2. 连续分配为什么简单又容易碎片化

最直接的办法是给每个进程一段连续物理内存。用一对基址和界限寄存器就能完成重定位与越界保护：

```text
若 0 <= 逻辑地址 < 界限：物理地址 = 基址 + 逻辑地址
否则：越界异常
```

当进程陆续创建和退出，空闲空间会变成很多洞。分配一段连续空间时常见选择是：

| 算法 | 规则 | 主要取舍 |
|---|---|---|
| First Fit | 从头找第一个足够大的洞 | 搜索通常较快，前部容易留下碎片 |
| Best Fit | 选能容纳请求的最小洞 | 可能制造大量难用的小洞，搜索更多 |
| Worst Fit | 选最大的洞 | 希望剩余部分仍可用，但不保证总体更好 |

**外部碎片**表示总空闲量足够，却被分散成多个不连续小洞，无法满足大块连续请求。移动已分配区域进行紧凑可以合并空洞，但复制成本高，而且要求地址能够重定位。

## 3. 分页怎样消除外部碎片

**分页（paging）**把虚拟空间分成等大的页，把物理内存分成相同大小的页框。一个进程的相邻虚拟页可以放到不相邻物理页框，由页表记录对应关系。

这样分配任意空闲页框即可，不要求给整个进程找一大段连续物理空间，所以普通分页没有连续分配意义上的外部碎片。

但分页仍有**内部碎片**：请求没有刚好填满最后一页，页内剩余空间属于已经分配的页，不能直接给别的对象使用。页越大，页表项和 TLB 压力可能越小，但最后一页浪费、缺页时搬运的数据量也可能更大。

## 4. 分段表达程序的逻辑区域

**分段（segmentation）**按代码、数据、栈等逻辑单位管理地址，每段有独立基址、长度和权限。逻辑地址可以表示为“段号 + 段内偏移”。它便于按逻辑区域共享和保护，但段长不同，会遇到外部碎片。

有些体系把分段与分页结合：先按逻辑段组织，再把段分页。现代 64 位通用系统更常以分页承担主要地址翻译，代码/堆/栈等逻辑区域由操作系统的软件结构和页权限表达。考试中的纯分段模型仍用于理解保护、共享和碎片差异。

| 方案 | 分配单位 | 主要碎片 | 地址空间视角 |
|---|---|---|---|
| 连续分配 | 可变长连续区域 | 外部碎片 | 一段连续空间 |
| 分页 | 固定大小页 | 内部碎片 | 对程序通常透明 |
| 分段 | 逻辑可变长段 | 外部碎片 | 代码、数据、栈等逻辑单位 |
| 段页式 | 段内再分页 | 页内碎片 | 兼顾逻辑分段与离散页框 |

## 5. 按需分页为什么需要页面置换

**按需分页**只在页面真正被访问时准备映射和物理页。地址是否合法、缺页怎样进入内核以及页表如何更新，由[虚拟内存](virtual_memory.md)主讲；本节只讨论一个合法缺页已经需要物理页、但当前没有空闲页框时怎样腾出空间。

若缺页时没有空闲页框，操作系统必须选择一个已有页面作为**牺牲页（victim page）**：

1. 选择要移出的页；
2. 若它是脏页，先把修改写回后备存储；
3. 修改原页表项，使其不再驻留；
4. 把需要的页读入该页框；
5. 更新页表并重新执行触发缺页的指令。

置换算法希望减少未来缺页，但系统不知道未来访问，只能利用历史近似。

## 6. FIFO、OPT 与 LRU

假设有 3 个页框，访问序列为：

```text
7 0 1 2 0 3 0 4
```

### FIFO：先进入的先移出

**FIFO（First-In, First-Out）**维护装入顺序。前三次装入 7、0、1；访问 2 时移出最早的 7，访问 3 时再移出 0，即使 0 很快又会用到。

FIFO 实现简单，却可能出现 **Belady 异常**：增加页框反而发生更多缺页。这说明“内存更多”不保证任何置换算法的缺页次数都单调下降。

### OPT：移出最晚才会再用的页

**最佳置换（OPT）**查看未来，移出未来最久不用或再也不用的页。它给定访问序列下缺页最少，但真实系统无法预知未来，因此主要作为理论下界来比较算法。

### LRU：移出最长时间没用过的页

**最近最少使用（Least Recently Used，LRU）**根据局部性，用“过去最久没访问”预测“近期也不太会访问”。精确 LRU 要在每次访问时维护全局顺序，硬件和并发成本较高，操作系统通常使用访问位、时钟算法或分代信息近似。

## 7. Clock 算法怎样近似 LRU

**Clock（时钟/二次机会）算法**把页面排成环，每页有访问位：

1. 指针查看当前页；
2. 访问位为 0，就选择它；
3. 访问位为 1，就清零并前进，给它第二次机会；
4. 继续直到找到访问位为 0 的页。

```mermaid
flowchart LR
    A["页 A R=1"] --> B["页 B R=0"] --> C["页 C R=1"] --> D["页 D R=0"] --> A
```

硬件在页面被访问时设置访问位，内核不需要维护精确时间顺序。改进版本还会参考脏位，优先淘汰无需写回的干净页。

## 8. 全局置换与局部置换

- **局部置换**：进程只能从分给自己的页框中选择牺牲页；进程之间隔离较强，但空闲资源不易动态共享。
- **全局置换**：可以从其他进程占用的页框中选择；整体利用更灵活，但一个进程的突发访问可能挤掉另一个进程的工作集。

页框分配可以按进程平均、按大小比例或按优先级进行。真实系统还要考虑内核页、文件页、匿名页、NUMA 节点、容器限制和不可换出页面，不能只用课堂算法解释所有行为。

## 9. 工作集与抖动

程序在一段时间内频繁访问的页面集合叫**工作集（working set）**。若所有活跃进程的工作集总量超过可用物理内存，刚换出的页很快又被访问，系统会反复缺页和 I/O，CPU 却没有完成多少实际计算。这叫**抖动（thrashing）**。

```mermaid
flowchart LR
    A["工作集装不下"] --> B["频繁缺页"] --> C["换入/换出增多"] --> D["程序进展变慢"] --> A
```

抖动时“增加更多并发任务”通常更糟。可行方向包括减少并发度、为关键工作集增加内存、降低单任务工作集，或限制造成压力的进程/容器。

**页故障频率法**根据进程的缺页率调整页框：缺页率过高时增加页框或暂停部分进程，过低时回收多余页框。核心仍是让活跃工作集能够驻留。

## 10. 文件后备、Swap 与 OOM

页面能否直接回收取决于它的后备来源：干净文件页可丢弃并在需要时重读；脏文件页要先写回；匿名页没有普通文件作为直接后备，若启用 Swap，可把暂时不用的内容换出。`mmap` 怎样建立匿名或文件映射见[虚拟内存](virtual_memory.md)。

Swap 不能把磁盘变成同等性能的 RAM。它提供容量缓冲和暂存位置，但大量活跃匿名页持续换入换出仍会抖动。关闭 Swap 也没有关闭虚拟内存、分页或页表。

若回收后仍无法满足必要分配，系统会进入 **OOM（Out Of Memory，内存不足）**。内核或容器内存控制器可能终止进程以释放资源；具体牺牲者规则属于实现策略，基础分析先确认容量上限、工作集和回收是否已经失效。

## 11. 常见误解

- **“分页没有碎片。”** 它消除了连续分配的外部碎片，但最后一页可能有内部碎片。
- **“LRU 就是 Linux 当前精确算法。”** 精确 LRU 成本高，真实内核使用近似与更多分类。
- **“缺页都是错误。”** 按需分配、文件首次载入和 COW 都会产生可正常处理的缺页。
- **“页框越多，任何算法缺页都更少。”** FIFO 可能出现 Belady 异常。
- **“Swap 等于虚拟内存。”** Swap 只是匿名页可能使用的后备之一。
- **“CPU 100% 才说明资源紧张。”** 抖动时 CPU 可能大部分时间等待页面 I/O。

## 12. 应用中的内存问题

| 场景 | 典型现象 | 应从什么基础分析 |
|---|---|---|
| Web 服务实例过多 | RSS 总和接近容量、回收频繁 | 工作集、全局竞争、并发度 |
| AI 推理加载权重 | 首次访问缺页，映射文件页可共享 | 按需分页、页缓存、工作集 |
| 数据库缓存 | 应用缓存与内核页缓存争 RAM | 文件页/匿名页、回收策略 |
| HFT 常驻状态 | 关键数据首次触碰或被其他负载挤出 | 工作集、缺页、资源隔离 |

先观察驻留内存、缺页、回收、Swap 和容器事件，再判断瓶颈。单看虚拟地址空间大小不能推出 RAM 压力。
