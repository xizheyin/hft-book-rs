# 超大规模虚拟网络：让 Agent 能通信，但不能越界

DNS、路由、TCP 和 Socket 的通用机制见系统子书的[网络基础](../../rust-hft/network/network_overview.html)；沙箱网络在其上增加虚拟接入、多租户隔离、工作负载身份和出口控制。

虚拟网络像大型园区的道路系统：房间要有地址，道路要能转发，门禁要决定谁能到哪里，出口海关要检查外发流量。只给每个沙箱一个 IP，并没有解决隔离、规模和故障问题。

本章分两条线：**数据面**真正转发每个包，**控制面**计算并下发地址、路由和访问策略。ACL（Access Control List，访问控制列表）是“谁能访问谁”的规则，egress 是离开沙箱网络的出口，trace context 是把一次请求跨服务关联起来的追踪标识。本章消息字段里的 TTL（Time To Live，生存时间）表示消息何时过期；不要把它与 IPv4 首部中每经过一台路由器就递减的 TTL 跳数混为一谈。

## 1. 单机数据路径

容器常见路径可以简化为：

```mermaid
flowchart LR
    P["沙箱进程"] --> NS["network namespace"]
    NS --> V1["容器侧 veth"]
    V1 --> V2["宿主侧 veth"]
    V2 --> R["网桥 / 路由 / eBPF 可编程数据路径"]
    R --> NIC["物理 NIC"]
```

veth（virtual Ethernet pair，虚拟以太网对）像一根两端网线，一端位于容器的网络命名空间，另一端留在宿主。VM 是另一条路径：guest 内的虚拟网卡经 virtio 等虚拟设备到 VMM/backend，再接宿主 TAP 或其他数据面；TAP 是把二层以太网帧交给用户态程序的虚拟接口，并不是 veth 的“VM 叫法”。eBPF 是 Linux 内核中的可编程执行机制，可实现转发、策略和观测。CNI（Container Network Interface，容器网络接口）规范定义运行时如何请求插件配置网络，但 CNI 本身不是某一种数据面实现。

## 2. 跨机：underlay 与 overlay

underlay（底层网络）是物理交换机和路由组成的真实网络。overlay（覆盖网络）在它上面封装租户虚拟网络，例如用隧道携带“内层”地址。

overlay 简化了地址与租户隔离，却增加封装字节、MTU（Maximum Transmission Unit，最大传输单元）、隧道端点状态和排障层次。若底层 MTU 是 1500 B，封装又消耗几十字节，而沙箱仍发送 1500 B 包，可能出现分片或黑洞。遇到“能 ping 小包、传大文件卡住”，应检查有效 MTU 与路径 MTU 发现。

## 3. 地址规模不是只有 IP 数量

假设 50,000 个沙箱，每个平均建立 40 条连接，就是约 200 万条活跃连接。若都经同一 NAT（Network Address Translation，网络地址转换）/conntrack（连接跟踪）节点，瓶颈可能先出现在连接状态、临时端口、哈希锁或 GC，而不是链路带宽。

策略规则也会爆炸。50,000 个主体若两两写 ACL，最坏是平方级关系。更合理的是用租户、角色、任务组和工作负载身份表达意图，再由控制面编译成可扩展的数据面规则。

## 4. “不离开物理边界”怎样落实

这不是给模型写一句系统提示，而是可验证的网络约束：

- 内部 Agent 通信使用私有地址与内部路由，不经公网。
- 默认拒绝跨租户和访问控制面管理网。
- 对允许的服务按工作负载身份授权，而不只信 IP。
- 外网访问经过受控 egress gateway/proxy，做目的地策略、审计、限速与内容大小限制。
- DNS 解析也受策略控制，防止域名重绑定绕过 IP allowlist。
- 禁止云元数据地址和内部凭证端点，除非通过专门代理。

物理边界、网络边界和权限边界不完全等价。流量留在同一机房，仍可能越过租户权限。

## 5. Agent 间通信协议

多 Agent 不应随意互开监听端口。平台可以提供受控消息通道：每条消息有发送者、接收者、run、schema、大小、TTL 和 trace context；队列或 RPC 层负责身份与背压。

例如一个 20 个 subagent 的任务，若每个 subagent 每秒向所有其他成员广播 50 KiB 状态，逻辑流量为：

```text
20 × 19 × 50 KiB/s ≈ 18.6 MiB/s
```

团队扩到 200 个，平方广播约变为 1.9 GiB/s。应改成分层汇总、共享不可变制品或按需订阅，而不是无限 full mesh。

## 6. 关键控制面对象

- sandbox endpoint：IP、MAC、节点、租户、run 与 epoch。
- network policy：谁可以访问哪个服务、端口和方向。
- service identity：负载身份及短期证书。
- route/tunnel state：目标前缀到节点或隧道端点的映射。
- egress policy：外部目的地、限额、审计与审批。

数据面应在控制面短暂不可用时继续执行最后一份有效策略，但策略过期或撤销如何处理要明确。安全撤销通常比新增连接更需要快速收敛。

## 7. 可观测性

至少要能从一次工具超时追到：DNS 延迟、连接建立、策略拒绝、重传、丢包、隧道、宿主队列和远端服务。指标应按租户与 workload class 聚合，避免把每个目标 IP 都做成高基数 label。

抓包很有用，却可能包含源码、Token 和秘密；生产抓包应有范围、时长、审批、脱敏和保留策略。

## 8. 典型失败路径

某次扩容给新节点配置了较小 underlay MTU，健康检查的小包全部成功；Agent 下载依赖时大包经 overlay 被丢弃，连接表现为随机卡死。客户端重试放大出口流量，问题只在新节点出现。

排查应比较节点、包大小和路径，观察重传与 ICMP，验证端到端有效 MTU。修复后要把大包连通性加入节点准入，而不只测 ping。

## 9. 做题方法：逐跳追一只数据包

1. 从沙箱进程开始，依次画 socket、虚拟接口、namespace/用户态网络栈、bridge/vSwitch、overlay 封装、宿主物理网卡、underlay、对端解封装和目标服务。
2. 每一跳标地址变化、路由表、MTU、策略执行点和可观测证据。出现丢包时按最早缺失的计数器/trace 点定位，不从应用 timeout 直接猜物理网络。
3. egress 题同时追 DNS 解析结果与真正连接 IP；策略需防重绑定、重定向和代理绕过，并把目标身份、端口与租户能力绑定。
4. 容量题分别计算沙箱地址、宿主路由/邻居、conntrack、overlay endpoint 和策略规则数量；IP 数量够不代表控制面与状态表能承载。
5. 在路由/策略版本更新中让部分节点迟到。数据包携带或日志记录配置 generation，控制面只把达到目标版本的节点算作 ready，旧规则不能被默认为已同步。

验算点：去程和回程都有合法路由；封装后不超过路径 MTU；每条允许流量有身份与最小策略；连接状态不会跨租户复用；trace 能指出包消失在沙箱、宿主、underlay 还是目标端。

## 10. 章末面试问题

**题目：设计允许同一任务 Agent 互通、又禁止跨租户与出物理边界的网络。**

**30 秒答法：**每个沙箱进入独立网络边界，通过 veth 或 tap 接入宿主数据面；控制面按租户、任务组和工作负载身份下发默认拒绝策略，只开放明确的 Agent 消息服务或目标端口。跨机可采用路由或 overlay，但要容量化隧道、MTU、连接状态与收敛时间。对外访问只能经身份化 egress proxy，禁止管理网和元数据端点，并记录 run/tool_call 级审计。控制面故障时数据面保留最后有效策略，撤销通过版本和过期机制收敛。

可能追问：

1. 为什么只按 IP 做授权不够？
2. overlay 与直接路由如何选择？
3. 如何避免 conntrack、NAT 端口或 DNS 成为热点？
4. 网络策略更新期间怎样避免短暂放通？

### 参考答案与解答

<details>
<summary>展开答案</summary>

1. IP 会复用、漂移，并可能经过 NAT；它不能单独表达租户、run、工具或服务身份。授权应基于控制面签发的工作负载身份与目标服务，IP/端口只作为数据面定位信息；身份到网络端点的绑定必须由可信组件建立并有过期时间。
2. 直接路由头部开销小、路径可观察，适合底层网络能承载沙箱地址和路由规模的环境；overlay 用隧道跨越现有网络，部署灵活但增加封装、MTU、隧道状态与 CPU 成本。选择前比较地址规模、路由表、跨域需求、可用 MTU、故障定位和性能，不应只比较单包速度。
3. conntrack 与 NAT 按源/目标分片并设置每租户连接上限、超时和容量告警，必要时绕过不需状态跟踪的路径；出口使用多地址/多代理扩展端口空间。DNS 做分层缓存、负缓存、TTL 与请求合并，同时保留权威服务冗余。压测要包含短连接风暴，而不只测稳定长连接。
4. 策略对象带单调版本，先在各节点安装新规则并确认就绪，再切换流量/身份引用；默认拒绝规则始终先存在，新增允许项最后生效，撤销时先阻断再清理旧规则。节点缺少所需版本时 fail closed，不能暂时回退成全放通。

</details>

## 11. 本章速记

- veth/tap 解决接入，路由/overlay 解决跨机，policy 解决权限。
- 物理不出界不代表租户不越权。
- 网络规模还包括连接状态、规则、DNS、MTU 与收敛。
- Agent 群体广播容易平方增长，应分层或按需通信。
- 外网出口是安全控制点，也是容量与单点风险。
