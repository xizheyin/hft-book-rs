# Agent 平台安全：能力票据、秘密、供应链与审计

> 难度：必会。本章承接沙箱隔离，重点回答：即使代码没有逃逸，Agent 还能怎样合法地做错事？

沙箱像保险柜，工具权限像保险柜里每把钥匙能开什么。把一个拥有管理员权限的工具放进最坚固的 VM，模型仍可能“合法调用”它删除生产数据。因此隔离与授权必须同时存在。

## 1. 授权决策的四个要素

每次副作用都检查：

```text
主体 principal + 动作 action + 资源 resource + 上下文 context
```

例如：`run r-123` 以用户 A 的委托，在审批单 P 未过期且参数哈希匹配时，允许对测试仓库 B 创建分支，但不允许推 main。

不要只给 Agent 一个长期“GitHub Token”。系统应签发短期、最小范围、绑定 run/tool/参数或资源的能力票据。工具服务验证票据，模型看不到上游主密钥。

## 2. 模型不是策略执行点

Prompt 可以提醒“不要访问生产”，但真正的拒绝必须由工具代理、网络、文件系统或目标服务执行。模型的自然语言判断适合提出请求，不适合成为唯一授权器。

高风险动作采用 prepare/commit：Agent 先生成结构化计划和影响预览；独立策略检查或人类审批签署参数摘要；提交阶段只接受完全相同的参数。审批“删除 3 个测试文件”不能被复用于“删除整个仓库”。

## 3. 秘密管理

- 长期秘密留在专门秘密服务，不进入镜像、Prompt、环境快照或日志。
- 沙箱通过工作负载身份领取短期凭证。
- 权限按目标服务、资源、动作和时间缩小。
- 工具输出、异常与 trace 先脱敏再持久化。
- run 终止、审批撤销或风险升高时可快速吊销。

环境变量比写在代码里好，但仍可被子进程、崩溃转储或调试信息读取；它不是完整秘密方案。

## 4. 间接提示注入

Agent 读取的网页、README、Issue、日志和 MCP 工具返回值都可能夹带指令。系统应把“数据”与“授权”分离：

- 外部内容标记来源与信任级别。
- 工具返回尽量使用有界 schema，限制嵌套、大小和可执行内容。
- 低信任数据不能自动提升到高权限工具。
- 高风险调用要求独立策略或审批，不因模型自信而放宽。
- 建立注入、越权、外泄和循环消耗的回归集。

过滤自然语言可以降低风险，却无法证明所有恶意指令都被识别；最小权限才是最后边界。

## 5. Memory 与跨会话污染

长期记忆是新的持久状态。写入前要记录主体、来源、租户、用途、TTL 和可信度；权限事实不能由模型从普通文本“总结后写入”。

读取必须按租户与用户过滤。支持回滚、删除和审计。被检索到的记忆仍是数据，不是系统指令；一个会话中的恶意内容不能影响另一个用户。

## 6. 软件供应链

Agent 经常安装依赖和运行仓库脚本，供应链风险高于固定服务：

- 基础镜像按 digest 固定并验证签名。
- 包管理器使用可信镜像、锁文件与哈希；未知安装脚本在更严格环境运行。
- 记录输入仓库 commit、依赖锁、工具链和构建制品 provenance。
- 对制品做恶意代码/秘密扫描，但不把扫描器当绝对证明。
- 缓存按权限域隔离，防止恶意租户投毒共享缓存。

Agent 修改安全测试与策略文件时应提高评审等级，防止“实现功能”的同时悄悄削弱门禁。

## 7. 成本型攻击

无限 Agent Loop、指数 subagent、反复模型调用和日志洪水会形成 Denial of Wallet。每个 run 要有 Token、工具次数、subagent、CPU/GPU、网络字节、存储和墙钟预算；接近预算时先降级，再确定性停止并给出可恢复状态。

假设每个 subagent 最多再创建 5 个，深度 4 的理论节点数是 `1+5+25+125+625=781`。限制总数比只限制每层 fan-out 更直接。

## 8. 审计与隐私

审计需要回答谁在何时以什么委托、调用哪个版本工具、对何资源执行什么、策略为何允许、结果是什么。审计日志应防篡改并与业务日志隔离。

同时遵守数据最小化：不要因为“方便复盘”就永久保存完整源码、Prompt、推理与秘密。保留期、访问目的、删除流程和内容采样必须明确。

## 9. 典型失败路径

一个外部 MCP 工具返回“检测结果”时夹带指令，让 Agent 调用内部文件读取工具并把内容作为下一次参数传回外部工具。两个工具单独看都有权限，组合后形成数据外泄。

修复需对工具建立信任域与信息流规则：外部低信任输出不能驱动高敏读取；敏感内容不能流向外部域；每次调用做参数级授权；高风险组合进入审批；trace 记录来源传播。

## 10. DeepSeek Agent Infra 面试怎么问

**题目：已经有强沙箱，为什么还需要工具权限系统？**

**30 秒答法：**沙箱防的是工作负载突破计算边界，工具权限防的是 Agent 通过合法接口越权。模型只负责提出结构化调用，后端按 principal-action-resource-context 做确定性授权；凭证短期、最小范围并绑定 run，敏感动作 prepare/commit 且审批绑定参数。外部内容和工具返回标记信任域，不能自动驱动高权限工具；同时限制 Token、步骤和资源预算，完整审计但最小化敏感内容。

可能追问：

1. 审批通过后参数变化怎样阻止？
2. MCP 工具描述或返回值投毒如何缓解？
3. 构建缓存如何防跨租户投毒？
4. 日志既要可审计又不能泄密，怎样取舍？

## 11. 本章速记

- 隔离防逃逸，授权防“合法越权”。
- 模型可以请求，不能独自批准高风险动作。
- 能力票据应短期、最小范围、绑定上下文。
- 外部内容、Memory 和工具输出都是不可信数据。
- 安全还包括供应链、成本预算、审计和隐私。
