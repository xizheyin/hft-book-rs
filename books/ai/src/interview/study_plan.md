# 冲刺学习计划：14 天、7 天与最后 24 小时

面试准备最容易出现两种错觉：看过等于会了，答案很长等于答得好。真正有效的训练必须产生可以检查的输出：30 秒答案、白板图、容量计算、故障处理、STAR 录音和错题修订。

本章给三套节奏。时间足够时优先使用 14 天版；只剩一周就用 7 天版；最后 24 小时只做收敛，不再打开十个新主题。每一天都遵循一个小循环：

```text
输入 30%：阅读和补概念
输出 50%：脱稿讲、画、算、答追问
纠错 20%：核对事实、记录不会、第二天复测
```

## 1. 30 秒答法：如何介绍自己的准备策略

> 我的准备按岗位主次分配：60% 用于 Linux I/O、VM/容器、存储、网络、控制面、HA 和事故响应；20% 用于 Agent 状态、工具、verifier 与安全边界；20% 用于简历事实、测量口径和真实事件。每天还有 60-90 分钟 Linux/Rust 实操，确保答案来自观察和代码，而不是只背书。

### 固定时间预算

- **核心系统 60%**：官方岗位直接要求的 OS、虚拟化、存储、网络、调度、控制面、可观测性与可靠性。
- **Agent 20%**：只补理解沙箱上层负载所需的模型、工具、状态、评测和安全执行。
- **简历 20%**：HFT、rustc/Buck2、Crates-Pro 与三篇重点论文的证据核验。

每天固定保留 60-90 分钟实操。推荐在 Linux VM 或容器环境进行；没有 root 权限时，选择不要求提权的 Rust 编码、`strace`、`perf`、`ss`、文件 I/O 和故障注入实验，不把“命令看过”算完成。

## 2. 开始前先建立四份卡片

不要急着从第一页顺读。先建立四份一页纸卡片，可以手写，但内容要能随时更新。

### 2.1 事实卡

只写可以公开、可以核验的事实：

- 某量化机构匿名；累计迁移与验证约 20 万行，负责关键数据路径。
- 在覆盖样本上验证语义一致性；离线 replay 的 p50/p99 改善 10%-20%。
- rust-lang/rust 106 PR，83 merged；rustc 与 unsafe API 两项代表工作随 Rust 1.90 发布。
- Buck2 RISC-V 相关 3 个 PR 均经 Meta upstream import 合入。
- Reaper：OOPSLA 2026 Revision。
- SkillFuzz、Rust 生态漏洞传播与函数级可达性：ICSE 2027 Under Review。
- FRIES：ISSTA 2024；其他论文和项目数字按[简历深挖](resume_drill.md)核对。

### 2.2 缺口卡

将“不知道”变成有限清单：

- `write`/`fsync`、页缓存、文件系统、块层和跨层排障。
- namespace/cgroup、容器、用户态内核、VM、快照和异构 OS。
- 临时块设备、共享卷、fencing、虚拟网络、MTU/conntrack 和出口。
- 控制面、租约、幂等、背压、HA、RTO/RPO、节点上下线和事故响应。
- Agent loop、工具 schema、checkpoint、verifier、prompt injection 和上下文边界。
- HFT 测量卡、三篇论文事实表、真实失败案例和评审反馈。

### 2.3 故事卡

至少准备六个 STAR+L 故事：HFT 迁移、SkillFuzz、rustc 诊断、Vec unsafe 检查、Buck2 RISC-V、Reaper。每张卡不超过 12 行，结果数字和论文状态必须准确。

### 2.4 白板卡

固定一张 DSec 架构图和一张任务状态机，能在 8 分钟内从空白画出；内容见[系统设计白板](system_design.md)。

## 3. 14 天完整版

建议每天 3-4 小时，其中固定 60-90 分钟实操、60-90 分钟系统原理、30-45 分钟 Agent 或简历、30 分钟复述纠错。对 freshman 来说，每天只设一个主主题；未通过验收就顺延，不追求按日期“打卡完成”。

### 第 1 天：岗位地图与 Linux/Rust 基线

- 阅读[官方岗位要求](../orientation/role_map.md)与候选人作战地图，确认 60/20/20 权重。
- 题库随机抽 20 题做基线，只记录会/模糊/不会。
- **实操 60-90 分钟**：用 Rust 写一个带超时和退出码捕获的子进程执行器；用系统工具观察进程树和资源。
- 输出：事实卡、缺口卡、30 秒定位和基线分数。

验收：能说出主岗六类系统职责；程序能回收子进程且错误可观察。

### 第 2 天：文件写入与 I/O 排障

- 学[一次文件写入](../runtime/file_write_path.md)：`write`、页缓存、writeback、块层、`fsync` 和目录持久化。
- **实操 60-90 分钟**：在 Linux 上写小型 Rust 程序比较 buffered write、批量写和 `sync_all`；用 `strace` 核对 syscall，记录口径而非追求漂亮数字。
- 演练题库 4-6、22、45。
- 输出：写入全链路图和一张 I/O p99 排障表。

验收：能区分已写、可见、原子和持久，能解释实验局限。

### 第 3 天：容器、VM 与快照

- 学[容器与 VM](../runtime/containers_and_vms.md)，理解 namespace、cgroup、capability、seccomp 和 guest kernel。
- **实操 60-90 分钟**：检查一个 Linux 容器/进程的 namespace、cgroup 与 limits；用 Rust 制造 CPU/内存/进程压力并观察限制，避免在宿主机无约束运行。
- 演练题库 7-8、15、20、56。
- 输出：隔离决策矩阵和快照恢复状态清单。

验收：不会把容器、VM 或某个产品说成绝对安全。

### 第 4 天：临时存储、共享卷与 fencing

- 学[沙箱存储](../runtime/storage.md)：基础层、工作层、共享层、制品层和一致性语义。
- **实操 60-90 分钟**：实现“临时文件 + `fsync` + `rename`”原子更新；写单元测试模拟重复创建和旧 epoch 写入被拒绝。
- 演练题库 21、23、37、51、66。
- 输出：存储分层图、卷状态机和 fencing 时间线。

验收：能解释为什么租约不足、为什么新 attempt 不能重复外部副作用。

### 第 5 天：虚拟网络与出口控制

- 学[虚拟网络](../runtime/virtual_network.md)：veth/tap、underlay/overlay、MTU、conntrack、DNS 与 egress。
- **实操 60-90 分钟**：在安全实验环境用 `ip`/`ss`/`ping`/抓包或等价工具观察连接、路由和包大小；无 root 权限时用普通 TCP 程序模拟超时、半关闭和有界重试。
- 演练题库 24、39、54-55。
- 输出：单机/跨机数据路径和“小包通、大包卡”排障树。

验收：能从一次工具超时追到 DNS、连接、策略、MTU、重传和远端服务。

### 第 6 天：生命周期、调度与控制面

- 学[沙箱生命周期与调度](../runtime/lifecycle_and_scheduling.md)和[控制面与数据面](../runtime/control_plane.md)：状态机、队列、租约、fencing、公平和背压。
- **实操 60-90 分钟**：用 Rust 实现简化任务状态机和带 epoch 的租约；加入陈旧 worker、重复消息和取消竞态测试。
- 演练题库 11-14、18、31、33-35、48-50、57、64-67。
- 输出：完整状态转移表和三条故障时间线。

验收：旧 epoch 永久失效；数据库断连后不得产生外部可见提交。

### 第 7 天：HA、观测与事故响应

- 学[可靠性与事故响应](../platform/reliability.md)、[可观测性](../platform/observability.md)和[容量规划](../platform/performance_capacity.md)：SLO、RTO/RPO、故障域、节点安全上下线、重试预算、熔断和事故复盘。
- **实操 60-90 分钟**：运行一个小服务并注入 kill、延迟和磁盘写失败；用日志、metric 或 `perf`/`strace` 找到第一处证据。
- 演练题库 36、38、46-47、52-53、58、68。
- 输出：一页事故时间线、止血/根因/防复发三层动作。

验收：不会用“加大超时”代替恢复设计，能给出可验证防复发机制。

### 第 8 天：Agent 最小共同语言

- 学 LLM 与 Agent 区别、模型调用、工具 schema、预算、状态、上下文和 verifier；模型推理只掌握 token、prefill/decode、KV Cache 的负载意义。
- **实操 60-90 分钟**：用 Rust 定义一个严格反序列化的工具协议，测试未知字段、越界参数、超时和输出截断。
- 演练题库 1-3、9-10、16-17、19。
- 输出：一次 Agent step 时序图和工具安全检查表。

验收：模型只提出意图，权限在模型外决定；结构化输出不等于安全。

### 第 9 天：Agent 安全、评测与 SkillFuzz

- 复述 SkillFuzz 准入、配对、轨迹审查和 800→569→79→48 漏斗。
- **实操 60-90 分钟**：为三个固定任务写 verifier，故意注入错误 oracle 和 flaky case，输出 `PASS/FAIL/INCONCLUSIVE`。
- 填 SkillFuzz 论文事实表，未知字段回到真实记录核对。
- 输出：威胁模型、评测有效性威胁和 2 分钟回答。

验收：不把 verifier 或配对实验说成绝对真理；论文状态为 Under Review。

### 第 10 天：HFT 与测量阻塞项

- 从空白画 Parser → Normalizer/Orderbook → Feature/Model → Alpha。
- 完整填写 HFT 测量卡；准备真实逐事件分叉和 Agent 门禁事件。
- **实操 60-90 分钟**：写一个双实现 replay/diff 小程序，定位第一个分叉；记录比较规则和不可比条件。
- 输出：30 秒、2 分钟答案和事件模板 A/B。

验收：测量卡关键字段不靠猜；准确说“覆盖样本验证一致性”和责任边界。

### 第 11 天：rustc、Buck2 与论文事实表

- 深挖一个 rustc 设计和 Buck2 PR 依赖，不以 PR 数量代替机制。
- 填完 Reaper 与供应链论文事实表，核对 SkillFuzz 表。
- **实操 60-90 分钟**：运行或阅读一个真实回归测试/基准，写下输入、oracle、环境和失败证据；若仓库不便运行，用最小 Rust 例子复现同类不变量。
- 输出：事件模板 C、三张论文事实表和最强两段研究答案。

验收：任何实验数字都有分母和定义；不能回答的字段明确标出而非猜测。

### 第 12 天：DSec 系统白板

- 按需求、OS/VM、存储、网络、控制面、容量、故障、安全和观测画完整白板。
- **实操 60-90 分钟**：用 Rust 或表格实现容量计算器，输入到达率、时长与资源向量，输出并发和节点余量；测试重尾和重试场景。
- 输出：35 分钟白板录像和三项待改进。

验收：核心系统占主要时间；练习假设与公司事实严格分开。

### 第 13 天：系统优先模拟一

- 模拟结构：核心系统 30 分钟、Agent 10 分钟、简历 10 分钟、行为/反问 5 分钟。
- **实操 60-90 分钟**：完成一道 Rust 并发/资源管理题或对故障代码做 `strace`/`perf` 诊断。
- 模拟者从文件写入、fencing、MTU、节点故障任选两条连续追问五层。
- 输出：评分、录音和最低三项。

验收：核心系统项至少 45/60；事实诚信无错误。

### 第 14 天：复测、模拟二与收敛

- 上午复测最低三项；下午再做一次系统优先模拟。
- **实操 60 分钟**：从前 13 天随机抽一个程序，在不看答案下重建并解释失败路径；不再引入新工具。
- 整理五页包：岗位/系统卡、I/O/虚拟化卡、DSec 白板、事实/STAR 卡、反问卡。
- 晚上轻量复述并保证睡眠。

验收：外部模拟者确认核心系统与总分达标；HFT 测量卡、三篇论文事实表和三个事件模板全部完成。

## 4. 7 天压缩版

每天约 4-5 小时，仍保持核心系统 60%、Agent 20%、简历 20%。每一天只设一个系统主轴，并保留 60-90 分钟实操；若实际只有两小时，优先完成“系统主轴 + 实操”，不要靠熬夜把所有阅读打勾。

| 天 | 系统主轴 | Agent/简历副轴 | 60-90 分钟实操与验收 |
|---|---|---|---|
| 1 | 岗位地图；`write`→页缓存→块层→持久化 | 事实卡、30 秒定位 | Rust 写入/`sync_all` + `strace`；能讲原子性与持久化 |
| 2 | 容器/VM/快照；临时块设备、共享卷、fencing | HFT 测量卡开始填写 | 检查 namespace/cgroup；实现 epoch 拒绝旧 writer |
| 3 | veth/tap、overlay/MTU/conntrack；控制面、租约、背压 | Agent 工具 schema | Rust 状态机 + 陈旧 worker/取消竞态测试；画网络排障树 |
| 4 | HA、RTO/RPO、节点上下线、事故与跨层观测 | SkillFuzz、verifier、安全边界 | kill/延迟/I/O 故障注入；输出事故时间线与 `INCONCLUSIVE` verifier |
| 5 | DSec 容量、OS/存储/网络/控制面完整白板 | HFT 与三张论文事实表、三个事件模板 | 容量计算器或一次 `perf`/`strace` 诊断；所有阻塞表不得靠猜 |
| 6 | 35 分钟系统设计与连续故障追问 | rustc/Buck2 最强故事 | Rust 并发/资源管理题；模拟后只修最低三项 |
| 7 | 系统优先完整模拟二与复测 | Agent、简历、行为和反问 | 重建一个前六天实验；外部评分核心系统至少 45/60 |

压缩原则：

- 不省略事实核验、故障题和模拟面试。
- 可以暂缓深度训练算法、CUDA kernel、完整 Transformer 推导和非岗位核心论文细节。
- 简历只保留最强三段深入，但 HFT 测量卡、三张论文事实表和三个真实事件模板不能省略。
- 任一实操若可能影响宿主机，转到受控 Linux VM/容器并设置资源上限。

## 5. 最后 24 小时

最后一天的目标是“减少波动”。通宵会同时伤害工作记忆、表达速度和情绪稳定，不值得。

### T-24 至 T-20：事实封板

- 核对事实卡、六个 STAR 和三种论文状态。
- 完成一次 1 分钟自我介绍和 HFT 5 分钟深挖。
- 把仍需查记录的数字标红；查不到就删掉细节，不猜。

### T-20 至 T-16：P0 概念回放

- 脱稿回答文件写入、容器/VM、存储 fencing、虚拟网络、控制面、HA 和事故题中最弱的 20 题。
- 只复习 `write/fsync`、隔离边界、MTU/conntrack、状态机、fencing、幂等、背压、RTO/RPO 和 verifier。
- 每题最多查 5 分钟，避免掉进新资料。

### T-16 至 T-12：一遍完整白板

- 35 分钟完成 DSec：需求 5 分钟、估算/API 7 分钟、架构 8 分钟、状态/故障 8 分钟、安全/取舍 7 分钟。
- 立即按评分表复盘，只修三个最明显的断点。

### T-12 至 T-9：一遍短模拟

- 30-40 分钟：自我介绍、两段简历、五道技术题、一个故障题。
- 练习先给结论；被指出错误时说清修正，不争辩。
- 准备 3-5 个真诚反问，例如团队当前最难的可靠性问题、成功标准、模型与执行平台边界、评测和发布流程。

### T-9 至 T-1：休息与通勤准备

- 留出完整睡眠；准备设备、网络、纸笔和安静环境。
- 不再做完整模拟，不读陌生大论文。

### T-1 至 T-0：低负荷热身

- 看五页最终卡片，不看整本书。
- 各说一遍 30 秒定位、一个 STAR、一个故障恢复和 DSec 架构主线。
- 提醒自己：未知可以承认，事实不能编造；先澄清，再回答。

## 6. 每日训练动作

### 6.1 30 秒 → 2 分钟 → 五层追问

同一题做三遍：

1. 30 秒只讲定义和结论。
2. 2 分钟加入机制、例子和限制。
3. 同伴连续问五次“为什么、如何证明、失败怎么办”。

如果 2 分钟答案只是把 30 秒答案放慢，就说明还缺结构。

### 6.2 白板回放

每天从空白画一张图，不照抄：

- 单数日画任务状态机。
- 双数日画 DSec 控制面/数据面。
- 每张图随机注入一个故障，并用另一种颜色画恢复路径。

### 6.3 初学者解释测试

找一个不了解项目的人，解释以下概念：

- 为什么 safe API 仍可能藏有 unsafe 缺陷；
- 为什么 Agent 的测试通过不能只听它自己说；
- 为什么重复消息不等于系统一定重复执行；
- 为什么 p99 改善不能证明所有请求都更快。

对方能复述，才说明表达真正通俗。

### 6.4 错题卡格式

```text
题目：
我第一次怎么答：
错误属于：事实 / 概念 / 推理 / 结构 / 表达
正确的 30 秒答案：
一个反例或故障：
明天复测时间：
```

## 7. 模拟面试评分表（100 分）

每一项必须写一句证据，不能只凭感觉打分。

| 维度 | 分值 | 高分标准 | 常见扣分 |
|---|---:|---|---|
| 核心系统机制 | 25 | 能讲文件 I/O、容器/VM、存储、网络及其故障语义 | 只会产品名；分不清可见、持久、租约和 fencing |
| 控制面、HA 与可靠性 | 20 | 状态、调度、背压、RTO/RPO、节点上下线和事故闭环完整 | 只画正常路径；没有故障域与防复发 |
| 跨层诊断与容量 | 15 | 会用 trace/metric/`strace`/`perf`，能按资源向量估算 | 只报平均数；没有固定 workload 和测量口径 |
| Agent 执行与安全 | 20 | 工具、状态、verifier、上下文、权限和注入边界清楚 | 让模型自行授权；结构化输出等同于安全 |
| 简历证据与真实事件 | 15 | 三段经历承受五层追问，测量卡/论文表/事件模板完整 | 团队结果冒充个人；STAR 只有项目摘要 |
| 表达与事实诚信 | 5 | 先结论、术语可解释、论文状态和保密边界零错误 | 夸大状态或数字；未知时猜测 |
| **总分** | **100** |  |  |

### 分数解释

- **90-100**：结构稳定，能接受高压追问；继续做少量随机模拟。
- **80-89**：具备竞争力；修最低两项和事实风险。
- **70-79**：知识存在但输出不稳；减少新内容，集中做白板和追问。
- **60-69**：有明显地基缺口；优先 Agent/分布式、安全和最强简历故事。
- **60 以下**：停止追逐高级名词，回到共同语言和一套完整系统设计。

表达与事实诚信虽然只有 5 分，却是门槛项：若把 Under Review 说成录用、把累计迁移说成个人手写，不能用其他高分抵消。核心系统三项合计 60 分，低于 45 分时不应由 Agent 或简历高分抵消。

## 9. 常见失分点

- 把学习时间全花在阅读，没有录音、白板和追问。
- 每天都换新主题，错题从未复测。
- 最后一天继续扩展 CUDA、训练算法或陌生论文，破坏稳定性。
- 模拟者只问友好问题，没有追问个人贡献、数字口径和失败路径。
- 评分只写“感觉不错”，没有逐项证据。
- 为了显得全面，在不熟悉的问题上猜内部实现或项目数字。
- 忽略睡眠和设备准备，导致会的内容说不清。

## 10. 本章速记

- 14 天：核心系统 7 天，Agent 2 天，简历 2 天，白板与模拟 3 天；每天另有 60-90 分钟实操。
- 7 天：I/O → 虚拟化/存储 → 网络/控制面 → HA/Agent 安全 → 白板/事实 → 双模拟，每天保留实操。
- 24 小时：事实封板、P0 回放、一遍白板、一遍短模拟、完整睡眠。
- 每天必须有输出：录音、图、计算、STAR 或错题复测。
- 目标分：第一次模拟 75，第二次 85；核心系统至少 45/60，事实诚信始终满分，并由外部模拟者而非只靠自评确认。
- 只记一个回答公式：**结论 → 机制 → 证据 → 失败 → 限制。**
- 只记一个定位：**把不确定的 Agent 行为放进可靠、可验证的执行边界。**
