# AI Agent Infra 面试题库：120 题与 P0/P1/P2 追问路线

题库不是背诵比赛。正确用法是：先遮住答案，在 30 秒内给结论；再用 2 分钟讲机制、取舍和验证；最后让同伴从答案里的任何名词继续追问。若只能复述本页文字，却不能画图、举例或说明限制，就还没有真正掌握。

时间权重按岗位主次分配：核心系统 60%，Agent 20%，简历 20%。题库保留恰好 120 题，并用三种**全书优先级**组织：**P0** 是最高优先的岗位主线，**P1** 是常见连续深挖，**P2** 是方向相关的扩展。LLM 知识仍以理解 Agent 负载和基础设施取舍为边界。

| 练习阶段 | 做哪些题 | 通过标准 |
|---|---|---|
| 第 0 遍技术红线 | 本页唯一权威清单中的全部 `[红线]` 题 | 闭卷结论 100% 正确；错一题就回章复习并在次日复测 |
| 第一遍 P0 | 除已单独验收红线外，所有标有 `[P0]` 的题 | 30 秒先给正确结论，再讲机制、失败模式和验证方法 |
| 第二遍 P1 | 所有标有 `[P1]` 的题，包括其中的红线题 | 红线结论仍为 100%；其余题能比较方案，并给出证据或计算 |
| 第三遍 P2 | `[P2]` 题与文末开放题 | 能承认边界，并说清怎样进一步验证 |

## 0. 两种零容错：技术红线与事实红线不能混

### 28 道技术红线：唯一权威清单

技术红线指基础机制的结论不能反着说。下面这张表是本书**唯一权威的 28 道技术红线清单**；对应题目标题中的 `[红线]` 只是定位标记，必须与本表题号完全一致，不能再维护第二份名单。

| 5 | `write` 成功、原子可见、`fsync` 完成和故障后持久化是不同承诺。 |

### 事实零容错：不计入上面的 28 道技术红线

事实零容错指候选人不能虚构或夸大个人经历：某量化机构保持匿名；Reaper 只能表述为 OOPSLA 2026 Revision；SkillFuzz 与 Rust 生态漏洞传播工作只能表述为 ICSE 2027 Under Review。团队规模、模型、硬件、SLA、失败案例和 DeepSeek 内部实现若没有简历或公开一手证据，就明确说未知并给验证方法，不能用推测补空白。

## 1. 30 秒答法：通用模板

面对技术题，可以先说：

> 我先给定义和结论，再说明它解决的失败模式。系统上我会画出状态与信任边界，给出一个主要方案和一个备选方案；最后用指标、测试或 verifier 说明怎样证明，并补充适用限制。

面对经历题，可以先说：

> 当时的约束是……，我负责……。我先定义了……不变量，再做了……，通过……验证。结果是……。这个结论只覆盖……，如果重做我会……。

## 2. P0 基础题：先把共同语言讲清楚

### 1. `[P0]` `[红线]` LLM 和 Agent 有什么区别？

答题要点：

- LLM 主要根据上下文生成下一个 token；Agent 是围绕模型增加状态、工具、环境反馈、停止条件和验证的执行系统。
- 模型回答错误是模型风险；Agent 还会产生文件、网络、权限和外部副作用，因此系统边界比聊天场景更重要。

### 2. `[P0]` 什么是 Agent Infra？

答题要点：

- 它是让 Agent 可运行的基础设施，包括任务 API、调度、模型路由、工具协议、沙箱、状态存储、观测、评测和审批。
- 高分回答要强调“模型提出意图，确定性系统控制权限和结果”，而不是只列框架名称。

### 3. `[P0]` `[红线]` 为什么模型能力强，不代表 Agent 系统可靠？

答题要点：

- 模型输出具有概率性，也可能受不可信上下文影响；工具、网络和外部服务还会独立失败。
- 可靠性来自权限边界、幂等、重试、状态机、verifier、回放和人工门禁，不能只靠更长 Prompt。

### 4. `[P0]` 从 `write()` 到数据真正落盘经过哪些层？

答题要点：

- 普通 buffered write 从用户缓冲区进入系统调用，经 VFS、具体文件系统和页缓存成为脏页，再由 writeback、块层、驱动和设备队列写向介质。
- `write` 还可能短写；即使返回完整长度，也通常只表示内核接受了数据，不等于掉电安全。还要根据恢复语义讨论 `fdatasync`、`fsync`、目录同步和远端副本确认。

### 5. `[P0]` `[红线]` `write`、`fsync`、原子可见和持久化有什么区别？

答题要点：

- `write` 成功、其他进程可见、更新原子和崩溃后仍存在是不同承诺；不能用一个“写成功”概括。
- 常见原子替换协议是写临时文件、同步文件、同文件系统 `rename`，再同步父目录；具体保证仍取决于文件系统和设备语义。

### 6. `[P0]` 页缓存何时提高性能，何时造成长尾？

答题要点：

- 命中页缓存可避免设备 I/O、合并小写，但脏页积累到阈值会触发集中 writeback 或写入节流，造成 p99 尖刺。
- 排查要同时观察 dirty/writeback、缺页、I/O 队列、设备延迟和内存压力；不能只看应用层耗时。

### 7. `[P0]` `[红线]` 容器、用户态内核与 VM 的隔离边界有何不同？

答题要点：

- 普通容器共享宿主内核；用户态内核重实现或代理大量系统接口；VM 使用 guest kernel 和 VMM/硬件虚拟化形成更强内核边界。
- 常见 KVM 路径中，vCPU 由宿主线程驱动；内存经过 guest 页表的 `GVA → GPA` 与 EPT/NPT 等第二阶段的 `GPA → HPA`，I/O 可用 virtio 共享队列减少传统设备模拟成本，但 virtio 不保证零拷贝或零退出。
- 选择要共同考虑攻击面、兼容性、异构 OS、启动、密度、I/O/网络开销和运维，而不是简单排序“谁更安全”；这些是公开通用机制，不能冒充 DeepSeek 内部实现。

### 8. `[P0]` `[红线]` namespace、cgroup、capability、seccomp 各解决什么？

答题要点：

- namespace 隔离进程可见视图；cgroup 计量和限制资源；capability 拆分 root 权力；seccomp 过滤系统调用；Linux Security Module（LSM，如 SELinux、AppArmor）通过内核安全钩子实施对象访问策略。
- 它们互补但都不是完整沙箱，还需文件、网络、身份、更新和宿主安全边界；这里的 LSM 与数据库的 LSM-tree 无关。

### 9. `[P0]` `[红线]` 什么是结构化工具调用？

答题要点：

- 模型输出工具名和符合 schema 的参数，执行器校验后调用真实工具，再把结果作为新观察返回。
- 结构化不等于安全；仍需鉴权、路径和网络控制、超时、输出限制及副作用审批。

### 10. `[P0]` 为什么工具参数要用 schema 校验？

答题要点：

- schema 能拒绝缺字段、类型错误、超范围值，并让版本演进和错误返回更清晰。
- schema 只验证“形状”，不能判断调用者是否有权限或业务语义是否合理，必须叠加策略检查。

### 11. `[P0]` `[红线]` 什么是幂等？

答题要点：

- 同一个逻辑请求执行一次或重复执行，最终可观察结果相同。例如客户端超时重试创建任务时，不应生成两个任务。
- 常用方法是稳定 idempotency key、唯一约束、状态检查和外部动作收据；并非所有副作用都天然可幂等。

### 12. `[P0]` `[红线]` 重试为什么可能让故障更严重？

答题要点：

- 大量客户端同步重试会放大流量；非幂等动作还可能重复扣费、发布或写入。
- 应分类错误，使用指数退避、随机抖动、重试预算和熔断；结果未知的外部写操作优先对账。

### 13. `[P0]` `[红线]` Agent 为什么需要状态机？

答题要点：

- 状态机明确 queued、running、waiting approval、verifying、cancelled 等合法迁移，避免多个 worker 对同一任务做矛盾动作。
- 每次迁移应带版本检查和事件记录，使暂停、恢复、取消和审计可实现。

### 14. `[P0]` checkpoint 应保存什么？

答题要点：

- 保存仓库基础快照与 diff、已完成 step、预算、结构化 Agent 状态、策略/模型/工具版本和外部动作收据。
- 不应只保存自由文本对话；也不应把秘密和无限增长的完整 stdout 全塞进热状态库。

### 15. `[P0]` `[红线]` 容器就是安全沙箱吗？

答题要点：

- 容器提供进程、文件和资源隔离能力，但通常共享宿主内核，默认配置不等于适合执行恶意代码。
- 还需非 root、只读基础层、cgroup、seccomp、网络默认拒绝、秘密代理和必要时更强的 microVM 隔离。

### 16. `[P0]` `[红线]` 什么是 prompt injection？

答题要点：

- 不可信文档、代码或工具输出包含诱导模型忽略原目标、泄露数据或执行越权动作的内容。
- 不能只靠 Prompt 防守；仓库文本不能修改权限，所有工具调用必须在模型外重新鉴权。

### 17. `[P0]` `[红线]` 最小权限原则如何用于 Agent？

答题要点：

- 每个任务只获得完成目标所需的工具、文件、网络、秘密和时间范围，能力令牌绑定 job 与动作。
- 读写权限分开，高风险外部写需要审批；任务结束立即撤销临时能力。

### 18. `[P0]` `[红线]` 控制面与数据面为什么要分开？

答题要点：

- 控制面管理期望状态、策略、调度、租约和版本；数据面真正启动沙箱、挂卷、转发网络和执行工具。
- 控制面短暂失联时，数据面只能在未过期策略和租约内工作；撤销、fencing 和重建收敛语义必须明确。

### 19. `[P0]` 为什么 trace 比普通日志更适合长程 Agent？

答题要点：

- trace 用 job、attempt、step 串起模型、工具、文件和 verifier 的因果关系，能定位第一个分叉点。
- 普通文本日志仍有价值，但缺少结构和上下文传播；两者都要脱敏、限长并设置保留期。

### 20. `[P0]` `[红线]` microVM 快照恢复时必须重置哪些状态？

答题要点：

- 若把快照克隆为新实例，实例/机器 ID、随机数状态、网络身份与旧连接、短期凭证、密钥和前一租户数据都不能原样复制。
- 一致恢复还要保存匹配的 vCPU 寄存器、guest memory、虚拟设备/中断/virtqueue 状态，并协调块设备快照；KVM dirty bitmap 只说明哪些内存页写过，不等于内存、磁盘或应用已经一致。
- 基础镜像、guest kernel、VMM、CPU 特性或设备模型升级时要做版本兼容门禁；恢复失败需要有界退回冷启动，并防止批量失败形成风暴。

### 21. `[P0]` 临时块设备、共享卷和对象存储怎样分工？

答题要点：

- 临时块设备适合每个 run 的兼容工作区；共享卷提供跨实例文件语义；对象存储适合不可变制品、日志和 checkpoint。
- 共享卷先定义可见性、锁、`rename`、缓存和分区语义；不能因为“大家都要文件”就把所有数据放进一个 POSIX 卷。

### 22. `[P0]` `strace`、`perf`、火焰图和 I/O 指标分别回答什么？

答题要点：

- `strace` 看系统调用、返回值和阻塞位置；`perf`/火焰图看 CPU 样本、热点和调用栈；I/O 指标看队列、延迟、吞吐、IOPS 和饱和。
- 工具会有观测开销和盲区，应先用低开销指标缩小范围，再做受控深挖，并固定负载与版本复现。

### 23. `[P0]` `[红线]` 存储租约为什么还需要 fencing token？

答题要点：

- 租约只表达“控制面认为谁当前拥有资源”；失联旧节点可能稍后恢复并继续写。
- 数据面必须比较单调递增 epoch/fencing token，永久拒绝旧 epoch，才能阻止两个 writer 同时认为自己合法。

### 24. `[P0]` veth、tap、underlay 和 overlay 分别处在哪一层？

答题要点：

- veth 常连接容器 network namespace 与宿主；tap 常把 VM 虚拟网卡接入宿主；underlay 是物理路由网络，overlay 在其上封装租户网络。
- overlay 带来 MTU、隧道状态和排障成本；网络隔离还需工作负载身份、策略、DNS 与受控 egress。

## 3. P1 深入追问：把简历与 Agent Infra 连起来

### 25. `[P1]` 请解释 HFT 迁移中的关键数据路径。

答题要点：

- 从 Parser、Normalizer/Orderbook、Feature/Model 到 Alpha 依次说明输入、状态和输出，强调逐事件因果顺序。
- 画出每个组件的所有者和验证点；策略细节保持匿名，不用“保密”回避通用机制。

### 26. `[P1]` Rust/C++ 双实现怎样做逐事件差分？

答题要点：

- 固定输入、配置和初始状态，为每个事件建立稳定身份，在多个组件边界记录可比较状态。
- 先找第一个分叉事件，再检查浮点规则、顺序、时间戳和隐藏状态；只比较最终输出会丢失定位信息。

### 27. `[P1]` 为什么事件顺序是语义的一部分？

答题要点：

- 订单簿和特征是有状态计算，相同事件集合换一个顺序可能得到不同结果。
- 需要定义同时间戳排序、重复、缺失和乱序处理，并让 replay 与线上路径共享这些规则。

### 28. `[P1]` 浮点输出不完全相等时怎么办？

答题要点：

- 先判断业务要求是位级一致还是允许绝对/相对误差；不要随意设置宽容阈值掩盖逻辑错误。
- 记录第一个误差来源，控制编译优化、运算顺序和硬件差异，并对误差累积做边界分析。

### 29. `[P1]` 能否由简历数字证明 Rust 比 C++ 快？

答题要点：

- 不能。简历只能证明在覆盖样本的特定离线 replay 中，迁移后 p50/p99 改善 10%-20%。
- 必须补充硬件、编译参数、数据、预热和 profile，才能判断收益来自实现、数据布局还是其他变化。

### 30. `[P1]` 为什么严格控制 `unsafe` 和 `RefCell`？

答题要点：

- 两者会把一部分别名、线程或运行时借用不变量交给开发者维护，扩大审计责任。
- 它们仍可在小而明确的边界使用；需要说明不变量、测试、基准和安全封装，而不是一律禁止。

### 31. `[P1]` Coding Agent 迁移中，人和 Agent 怎样分工？

答题要点：

- 简历明确：人负责架构、业务语义、风险判断和最终审计；Agent 在受约束 harness 中做代码理解、迁移、测试等任务。
- 面试要补一个门禁拒绝错误输出的实例，并准确区分团队累计产出与个人责任。

### 32. `[P1]` HIR 与 MIR 有何区别？

答题要点：

- HIR 是 AST 经宏展开、名称解析和降糖后的高层中间表示；类型检查作用于 HIR，完整的 typed 表示可在 THIR 中看到，之后再构建控制流更明确的 MIR。
- MIR 更适合数据流、借用、优化和静态分析，但具体版本细节应以对应 rustc 源码为准。

### 33. `[P1]` rustc 诊断共享状态污染怎样治理？

答题要点：

- 简历事实是重构主诊断与子诊断参数生命周期，自动完成快照、翻译、清理和恢复，并加入同名异值不变量检查。
- 回答时需补真实复现和异常路径，说明为什么顺序正确以及测试怎样阻止回归。

### 34. `[P1]` UB 前置条件检查为什么做成可选？

答题要点：

- 检查能更早暴露违反 unsafe 契约的问题，但可能增加运行或编译成本，也不能覆盖所有 UB。
- 简历证据包括 Vec/String 路径的 run-fail 测试和 rustc-perf；具体开销只按实际记录回答。

### 35. `[P1]` host、target 和 toolchain 有什么区别？

答题要点：

- host 是编译工具运行的平台，target 是生成程序面向的平台，toolchain 包含对应编译器、标准库和相关工具。
- 交叉编译中 host 与 target 不同；构建通过也不等于目标机运行验证完成。

### 36. `[P1]` 为什么把 Buck2 RISC-V 支持拆成 3 个 PR？

答题要点：

- 简历给出的范围跨主机识别、平台约束、target/toolchain、发布矩阵和 artifact 映射，按依赖拆分能降低评审与回滚风险。
- 要能画出实际依赖顺序，并说明每一步在 RISC-V Debian 上验证到什么程度。

### 37. `[P1]` 块存储、文件存储和对象存储应怎样选择？

答题要点：

- 块存储提供原始块和文件系统自由度；文件存储提供目录/锁/共享语义；对象存储按 key 管不可变或大对象，通常不提供完整 POSIX 语义。
- 选择取决于小文件元数据、共享写、一致性、快照、恢复、成本和生命周期；Agent 工作层与持久制品往往需要不同介质。

### 38. `[P1]` Kafka 的“至少一次”对消费者意味着什么？

答题要点：

- 消息可能重复，消费者必须用事件 id、唯一约束或版本检查做到幂等。
- 数据库写入与 offset 提交之间会有故障窗口；要说明提交顺序、重放和对账，不轻率声称端到端 exactly-once。

### 39. `[P1]` 小包能通、大文件卡住，你怎样排查虚拟网络？

答题要点：

- 先按节点、路径和包大小对比，检查端到端 MTU、隧道封装、PMTU/ICMP、分片、重传和策略拒绝。
- 若只在新节点发生，检查 underlay MTU 与数据面配置；同时防客户端重试把出口和 conntrack 进一步打满。

### 40. `[P1]` 什么是抽象解释？

答题要点：

- 它不枚举所有具体运行状态，而是在抽象域中保守地传播可能状态，通过 join 和 fixpoint 处理分支与循环；抽象域不必有限，收敛可依赖有限高度或 widening/narrowing。
- 抽象越粗越可扩展，但误报可能更多；要用已知缺陷和真实扫描评估召回、精确率和性能。

### 41. `[P1]` 怎样面对 Reaper 51.6% 的告警级精确率？

答题要点：

- 不回避：约一半告警不是评测定义下的真实缺陷，使用成本取决于告警数量、排序和人工审查时间。
- 同时给出召回和真实生态结果，再分析误报类别与适用场景；论文状态只能说 Revision。

### 42. `[P1]` SkillFuzz 为什么做有/无 Skill 配对？

答题要点：

- 同一任务比较使用 Skill 与不使用 Skill 的运行，有助于判断错误是否由 Skill 诱发，而非任务天然困难。
- 配对不能自动消除模型随机性、oracle 错误或样本偏差，还需准入、重复试验和轨迹审查。

### 43. `[P1]` verifier 自己错了怎么办？

答题要点：

- 用参考解先验证任务和 verifier 能得到预期结果，对 verifier 做单元、边界和变异测试。
- 对不稳定或无唯一答案任务标为不确定并拒绝自动归因；必要时双人审查或使用多个独立证据。

### 44. `[P1]` 包依赖可达与函数调用可达有何区别？

答题要点：

- 包进入依赖图只说明代码可能存在；函数级调用路径更接近实际触达，但仍不等于输入可控或漏洞可利用。
- feature、默认配置、泛型单态化和动态分派会改变可达性，结论必须绑定构建配置。

## 4. P0 故障题：看你能否安全收场

### 45. `[P0]` 沙箱文件 I/O 的 p99 突然升高，你怎样跨层定位？

答题要点：

- 先拆应用 syscall、页缓存/dirty、文件系统锁、块层队列、设备和远端副本延迟，再按节点、租户、文件大小和时间窗口对比。
- 检查日志洪水、inode/配额、集中 writeback、GC、慢盘和重试放大；止血应限流和隔离，不只增大超时。

### 46. `[P0]` 节点心跳丢失后，为什么不能立即重调度全部沙箱？

答题要点：

- 网络抖动可能让旧节点仍在执行；立即批量重调度会造成双写、镜像/存储风暴和级联过载。
- 先隔离故障域、停止旧 epoch 提交，用租约与 fencing 确认所有权，再按受控速率恢复，并保留人工熔断开关。

### 47. `[P0]` shell 命令超时但子进程仍在运行怎么办？

答题要点：

- 在独立进程组或沙箱内执行，超时先停止接受后续动作，再终止整个进程树并回收资源。
- 使用 cgroup 限制 fork、CPU 和内存；仅杀父进程可能留下孤儿进程。

### 48. `[P0]` worker 执行一半崩溃，怎样恢复？

答题要点：

- worker 依靠带过期时间和单调 fencing epoch 的租约成为单写者；租约过期后，新 worker 用更高 epoch 从已提交检查点创建新 attempt，数据面永久拒绝旧 epoch。
- attempt/step id 用于追踪，外部副作用使用跨 attempt 稳定的 `logical_effect_id` 幂等或对账；否则恢复会生成新 key 并重复动作。

### 49. `[P0]` 队列重复投递同一任务怎么办？

答题要点：

- 接受至少一次投递，用 event id、job version、当前有效租约与 fencing epoch、唯一约束拒绝重复推进。
- 重复投递是正常情形，不应依赖“消息绝不会重复”的假设。

### 50. `[P0]` 状态数据库不可用时，运行中沙箱要继续吗？

答题要点：

- 只有仍持有未过期本地租约的低风险纯计算才能在有界窗口内继续；不得产生外部可见提交、获取新权限或越过本地 deadline。
- 租约到期或无法续租立即停止；控制面停止调度新任务并告警，恢复后按 event id 与 fencing epoch 对账。

### 51. `[P0]` 检查点引用的对象损坏怎么办？

答题要点：

- 内容寻址和校验和能在读取时发现损坏，元数据只有在对象持久化成功后才指向它。
- 尝试上一检查点或重新执行可幂等 step；若证据不足，标记失败而非悄悄跳过。

### 52. `[P0]` 测试偶尔通过、偶尔失败，verifier 怎么判？

答题要点：

- 将其标为 flaky 或 inconclusive，不应一次通过就自动放行；固定依赖、随机种子、时间和并发条件。
- 记录多次结果与失败分布，将修复 flake 与修复目标 bug 分开。

### 53. `[P0]` `[红线]` 外部 API 超时，不知道写操作是否成功，能直接重试吗？

答题要点：

- 不能盲目重试。先使用稳定幂等键查询结果或读取动作收据，对账后再决定。
- 若对端不支持幂等与查询，高风险写应禁用自动化或要求人工处理与补偿流程。

### 54. `[P0]` 仓库 README 命令 Agent 上传凭证，怎样阻止？

答题要点：

- README 是不可信数据，不能改变工具策略；网络默认拒绝，秘密不进入沙箱或提示。
- Tool Proxy 对每次调用重新鉴权，外发目标受 allowlist 和数据限制，策略拒绝写入审计。

### 55. `[P0]` 日志中发现秘密泄漏怎么办？

答题要点：

- 立即撤销和轮换凭证，限制日志访问并确认传播范围；保留受控审计证据。
- 长期修复是让秘密通过代理使用而非暴露给不可信进程，脱敏只能作为第二道防线。

### 56. `[P0]` 发现可能的沙箱逃逸怎么办？

答题要点：

- 隔离受影响宿主与租户，停止相关 worker 池，保留取证并轮换宿主可接触的能力。
- 修补镜像/内核后分阶段恢复；用更强隔离、最小宿主权限和小爆炸半径降低影响。

### 57. `[P0]` 取消请求与“任务成功”同时发生，状态如何决定？

答题要点：

- 用状态版本和 compare-and-swap 定义合法竞争结果；终态不可被另一条迟到事件覆盖。
- 产品语义要提前决定：若 verifier 已原子提交成功，取消返回终态；否则先递增 cancellation epoch，让排队和在途的旧能力失效，再终止进程、清理资源并进入 `CANCELLED`。

### 58. `[P0]` Agent 的摘要漏掉关键约束，后续动作跑偏怎么办？

答题要点：

- 关键约束、审批、预算和未完成副作用必须存结构化状态，不能只靠自由文本摘要。
- trace 保留来源引用，发现分叉后可回放；摘要器本身也要版本化和回归评测。

## 5. P0 容量与性能题：会算，才会做取舍

### 59. `[P0]` 怎样估算同时需要多少沙箱？

答题要点：

- 先估高峰到达率和平均任务占用时间，用并发约等于到达率乘停留时间得到一阶结果。
- 再按任务类型、长尾、重试、预热池和资源画像校正，不能只报一个平均数。

### 60. `[P0]` 怎样估算模型网关峰值？

答题要点：

- 高峰任务/秒乘每任务平均模型调用数得到请求率，再分模型、输入长度和输出长度统计 token 速率。
- 请求数相同但长上下文成本可差很多；还要考虑 cache hit、fallback 和重试放大。

### 61. `[P0]` Agent 成本为什么容易失控？

答题要点：

- 多轮把历史与仓库重复送入模型，循环和失败重试又会放大 token、沙箱时间与日志量。
- 使用总预算、step 上限、按需上下文、前缀缓存、模型路由和每成功任务成本指标。

### 62. `[P0]` 怎样设计轨迹存储？

答题要点：

- 热层保存结构化事件和索引，大 stdout、模型内容和文件转对象存储；用 cursor 流式读取。
- 设置按敏感度和用途的保留期、压缩与删除策略，审计数据和 debug 数据分开。

### 63. `[P0]` 怎样降低沙箱冷启动？

答题要点：

- 维护按镜像/资源类型的小规模预热池，复用只读基础镜像、仓库对象和依赖缓存。
- 不复用租户可写层或秘密；预热过多会浪费资源，需根据到达分布动态调整。

### 64. `[P0]` 多租户怎样公平调度？

答题要点：

- 使用租户级加权公平队列和并发、token、CPU、存储多维配额，防止大任务独占。
- 预留系统和交互任务容量，长期任务可抢占到检查点，但必须保证副作用安全。

### 65. `[P0]` `[红线]` 什么叫背压？

答题要点：

- 下游变慢时，上游减少生产或排队，而不是无限堆积和重试；它是把资源真实能力反馈给调用者。
- 可通过队列上限、并发令牌、预计等待、429/重试时间和 admission control 实现。

### 66. `[P0]` 哪些内容可以缓存？

答题要点：

- 不可变仓库对象、依赖包、镜像层、确定性只读工具结果和稳定模型前缀可以按哈希缓存。
- 带权限、时效或外部状态的结果要把租户、版本和策略纳入 key；错误缓存可能泄密或返回过期事实。

### 67. `[P0]` 队列如何分片？

答题要点：

- 可按资源类型建立池，再在池内按租户或 job hash 分片；同一 job 的状态事件需保持可解释顺序。
- 热租户会造成热点，必须结合虚拟分片、配额和 work stealing，而不是只选一个字段固定分片。

### 68. `[P0]` SLO、RTO 和 RPO 分别约束什么？

答题要点：

- SLO 描述正常服务目标；RTO 约束故障后多久恢复；RPO 约束最多允许丢失多少已提交状态或数据。
- Agent 平台应分开控制面可用性、排队、取消、平台执行和任务正确性，并用故障演练验证恢复目标而非只写数字。

### 79. `[P0]` 怎样把研究原型变成工程系统？

答题要点：

- 从明确输入/输出和失败模式开始，把实验 oracle 变成版本化 verifier，把自由流程变成状态机和可观测事件。
- 增加隔离、预算、幂等、回归、发布和用户反馈；论文指标不能直接当生产 SLO。

### 80. `[P0]` 为什么应该选择你？

答题要点：

- 差异化不是“懂 Rust”，而是同时有生产低延迟迁移、编译器上游、安全分析和 Agent Skill 归因评测的证据。
- 结论保持克制：能为 Agent 执行层带来边界、不变量、回放和 verifier 思维；模型/GPU 缺口会用明确计划补齐。

## 7. P0 系统地基专项：从代码一直追到机器

这组题补齐操作系统、网络、存储和分布式系统的“下一层为什么”。如果某个答案仍像陌生名词表，先回到[计算机系统地基](../systems/computer_execution.md)，按执行路径重新建立因果关系。

### 81. `[P0]` `[红线]` 用户态和内核态为什么要分开？

答题要点：

- 普通应用运行在受限的用户态，不能任意改页表、控制设备或访问别的进程内存；内核态掌握这些全局资源。隔离让一个应用错误不至于直接破坏整台机器。
- 应用通过受控的系统调用入口请求内核服务。切换有成本，但真正昂贵的往往是调度、缺页、I/O 等后续工作，不能把所有慢都归因于“进内核”。

### 82. `[P0]` `[红线]` 系统调用和上下文切换是一回事吗？

答题要点：

- 不是。系统调用通常是同一个线程从用户态进入内核态；上下文切换是 CPU 改去运行另一个线程或进程，需保存和恢复执行状态。
- 系统调用可能立即返回，也可能因等待 I/O 睡眠并触发调度；排查时要区分 syscall 次数、阻塞时间、调度等待和 CPU 迁移。

### 83. `[P0]` 进程和线程分别拥有什么？

答题要点：

- 进程是资源与隔离容器，通常拥有独立虚拟地址空间、文件描述符表和安全身份；同一进程内线程共享这些资源。
- 每个线程仍有自己的寄存器、程序计数器和栈。共享让通信便宜，也让数据竞争和一个线程破坏全进程成为风险。

### 84. `[P0]` 文件描述符到底是什么？

答题要点：

- 它是进程内的一枚小整数，索引到内核维护的打开文件对象；对象可能代表普通文件、socket、pipe 或事件源。
- `fork`、`dup` 后多个描述符可能共享同一打开对象和文件偏移。泄漏会耗尽进程或系统上限，需观察 `/proc/<pid>/fd` 和错误码，而不是盲目加上限。

### 85. `[P0]` 调度器为什么会让明明有 CPU 的请求仍然变慢？

答题要点：

- 可运行线程要在有限 CPU 上排队；优先级、CPU 配额、亲和性、抢占、NUMA 和其他租户都会影响真正获得 CPU 的时间。
- 先区分运行时间与 run-queue 等待，再看 CPU 利用率、负载、cgroup throttling 和 PSI。总利用率不高也可能是单核热点或配额受限。

### 86. `[P0]` `[红线]` 为什么进程使用虚拟地址，而不直接使用物理地址？

答题要点：

- 虚拟地址让每个进程看到近似独立、连续的空间；内核用页表把虚拟页映射到物理页，并赋予读写执行权限。
- 这支持隔离、按需分配、共享库、内存映射文件和写时复制。代价是地址翻译、页表内存和缺页处理。

### 87. `[P0]` TLB 为什么会影响性能？

答题要点：

- Translation Lookaside Buffer 是 CPU 缓存最近地址翻译的小表；命中时不必逐级遍历页表。
- 工作集跨越很多页面、访问很随机或频繁切换地址空间时，TLB miss 会增加开销。大页可能减少 miss，但会带来碎片、分配和回收取舍。

### 88. `[P0]` `[红线]` 缺页一定表示程序在读磁盘吗？

答题要点：

- 不一定。minor fault 可能只是首次建立到已有物理页的映射；major fault 才通常需要等待存储把数据读入。
- 匿名页首次触碰、写时复制和 `mmap` 文件都可能产生缺页。要结合 major/minor fault、I/O 和内存压力判断，不能只看到“page fault”就断言磁盘慢。

### 89. `[P0]` 写时复制（COW）解决什么问题？

答题要点：

- `fork` 后父子进程先共享只读物理页；只有一方写入时，内核才复制该页，从而避免立即复制整个地址空间。
- 它让创建进程更便宜，但大内存父进程被子进程大量写时会突然增加缺页、内存和延迟；快照方案也要考虑类似的首次写成本。

### 90. `[P0]` Linux 什么时候会 OOM，为什么不能只看 free 内存？

答题要点：

- 内存申请无法通过回收、换出或其他策略满足时，系统或 cgroup 可能触发 OOM 处理。可回收页缓存、匿名页、内存承诺和 cgroup 上限都会影响结果。
- 诊断要看工作集、`memory.current/events`、缺页、swap、PSI 和内核日志；Agent 沙箱还需定义被杀任务的状态、重试和制品清理。

### 91. `[P0]` Mutex、spinlock 和原子操作怎样选择？

答题要点：

- 等待可能较长或线程可以睡眠时用互斥锁；临界区极短且不能睡眠的底层场景才考虑自旋；简单计数或状态转移可用原子操作。
- 原子不等于整个算法正确，无锁也不自动更快。先保证不变量，再测争用、等待、缓存抖动和尾延迟。

### 92. `[P1]` 原子操作已经不可分割，为什么还需要内存序？

答题要点：

- 原子性只保证某次读改写不被撕裂；多核还可能以不同顺序观察其他内存访问。内存序约束这些观察关系。
- acquire/release 常用于“发布数据后再发布就绪标志”；最弱的 relaxed 只保证该原子本身。面试中先画 happens-before，不要凭感觉堆最强顺序。

### 93. `[P1]` `futex` 为什么能让用户态锁又快又能睡眠？

答题要点：

- 无争用时，锁可先在用户态用原子操作完成，不进入内核；发生争用时，再通过 futex 让等待者睡眠或唤醒。
- 这只是底层机制，公平、优先级反转、惊群和所有者死亡仍需上层锁实现处理。

### 94. `[P0]` 死锁的四个必要条件是什么，工程上怎样预防？

答题要点：

- 互斥、持有并等待、不可抢占、循环等待同时成立时才可能死锁。
- 常用办法是全局锁顺序、缩短临界区、避免持锁做 I/O、超时只用于止损，以及用线程 dump/锁等待图找到环；超时本身不会恢复被破坏的不变量。

### 95. `[P1]` `epoll` 和 `io_uring` 的核心差别是什么？

答题要点：

- `epoll` 主要通知“哪些文件描述符现在就绪”，应用随后执行非阻塞 I/O；`io_uring` 用共享提交/完成队列表达异步操作，完成后取结果。
- 两者都不是自动加速器。负载、内核版本、操作类型、批处理、安全面和生态成熟度决定选择，必须基准测试。

### 96. `[P0]` `[红线]` 异步任务被取消时，资源和副作用会自动回滚吗？

答题要点：

- 不会。future 被丢弃可能停止后续代码，但已经发出的网络请求、文件写入或外部动作可能仍在发生。
- 要定义取消安全点、资源所有权、超时传播和结果对账；用有界队列和并发令牌做背压，避免“异步”变成无限积压。

### 97. `[P0]` `[红线]` TCP 的流量控制和拥塞控制分别保护谁？

答题要点：

- 流量控制根据接收窗口避免发送方压垮接收方缓冲；拥塞控制根据网络反馈调整在途数据，防止拥塞崩溃、缓解路径压力，并尝试在竞争流之间共享容量，但不保证所有 RTT、算法和连接数下绝对公平。
- 丢包或超时会触发重传，但重传增加延迟和带宽。应用层超时应按实际协议覆盖 DNS、TCP 或 QUIC 建连、TLS/QUIC 握手、排队和服务时间，并留出取消预算。

### 98. `[P0]` 一次 HTTPS 请求在真正发送业务数据前发生什么？

答题要点：

- 对典型 HTTP/1.1 或 HTTP/2 HTTPS，请求通常先做 DNS 和路由选择，再建立 TCP、完成 TLS 握手并验证身份，随后传输 HTTP 数据。HTTP/3 则使用基于 UDP 的 QUIC，并把 TLS 1.3 握手集成进 QUIC。
- 连接复用可摊薄握手成本；0-RTT 可能更早发送应用数据，却有重放风险，只应承载协议明确允许重放的操作。排障要按实际协议拆 DNS、连接/QUIC、握手和首字节，不能只看一个总超时。

### 99. `[P0]` HTTP/1.1、HTTP/2 和 gRPC 的关系是什么？

答题要点：

- HTTP 语义跨版本定义；HTTP/1.1 使用文本式消息格式，HTTP/2 使用二进制分帧并在一条连接上多路复用。gRPC 通常在 HTTP/2 上承载强类型消息与流式 RPC。
- 多路复用不能消除 TCP 层丢包影响；gRPC 的 deadline、状态码、重试和幂等仍需应用显式设计。

### 100. `[P0]` 四层和七层负载均衡怎样选择？

答题要点：

- 四层主要按 IP、端口和连接转发，协议无关且路径较短；七层理解 HTTP/RPC，可按路径、头和租户路由并执行更细策略。
- 七层可观测与治理更丰富，也多一次解析和信任边界。健康检查要反映真实服务能力，不能只检查端口存活。

### 101. `[P0]` inode、dentry 和目录项分别在做什么？

答题要点：

- inode 保存文件元数据和数据位置，文件名位于目录记录中；VFS 用 dentry 缓存路径组件到 inode 的解析结果。
- 因此重命名主要改变目录关系，打开的文件描述符仍可指向原对象；删除名字后，文件可能要等最后引用关闭才真正释放。

### 102. `[P0]` 文件系统 journal 和数据库 WAL 是一回事吗？

答题要点：

- 两者都利用“先记录可恢复意图，再更新主体”的思想，但保护层次不同：文件系统 journal 关注文件系统元数据或数据一致性，数据库 WAL 关注事务与数据库页恢复。
- 数据库提交不能因为底层文件系统有日志就跳过自身 WAL 和同步协议；还要考虑设备缓存、写入顺序和副本确认。

### 103. `[P0]` B-tree、LSM-tree 和 MVCC 分别解决什么问题？

答题要点：

- B-tree 让点查和范围扫描沿平衡树定位；LSM-tree 通常先追加 WAL、更新内存有序表，再 flush 为 SST 并后台 compaction；MVCC 用多个版本让读写并发并提供快照。
- LSM 往往提高写入吞吐，却会带来读放大、写放大和 compaction 长尾；MVCC 还需清理旧版本，不能把三者当互斥替代品。

### 104. `[P0]` `[红线]` 线性一致性、最终一致性和 quorum 是什么关系？

答题要点：

- 线性一致性要求每次操作看起来在调用与返回之间某一瞬间生效；最终一致性是在停止新写、通信最终恢复且反熵/修复流程继续推进的前提下，副本最终收敛。
- quorum 是读写副本数量的机制，不自动等于线性一致性；版本、并发写冲突、故障检测和读写协议仍决定语义。

### 105. `[P0]` `[红线]` Raft 怎样避免出现两个合法 leader？网络分区时呢？

答题要点：

- 每节点每任期只投一票，加上多数派交集，保证同一任期至多一个 leader；候选日志必须至少与投票者一样新，这条选举限制再配合日志匹配与提交规则，让已提交条目被后续 leader 保留。
- 少数派旧 leader 可能暂时仍自认为是 leader，所以外部资源写入还需 epoch/fencing token 拒绝旧持有者；“多数派共识”不能约束协议之外的存储。

### 106. `[P0]` Little's Law 能怎样帮助估算沙箱并发？

答题要点：

- 稳态下平均在系统中的任务数约等于平均到达率乘平均停留时间：`L = λW`。例如每秒 20 个任务、平均占用 30 秒，一阶并发约 600。
- 它不替代分布分析；突发、重尾、重试、资源异构和预热都要另外留余量。

### 107. `[P0]` `[红线]` 为什么平均延迟很低，p99 仍可能很差？什么是 coordinated omission？

答题要点：

- 排队、暂停、缓存未命中、compaction、重传和少数慢依赖都会只影响尾部；平均数会把它们稀释。
- 压测器若在系统变慢时也停止发请求，就漏记本应到达的等待，称为 coordinated omission。应采用符合真实到达过程的负载并报告完整分位数。

### 108. `[P0]` 一个 Agent 工具调用 p99 突然翻倍，怎样跨层排查？

答题要点：

- 先确认影响范围与时间线，再把总耗时拆成队列、调度、模型、DNS/connect/TLS、远端服务、文件 I/O 和 verifier；找第一个偏离基线的 span。
- 优先使用既有遥测；需要 `strace`、`perf` 或抓包时，只在已授权的受控测试/灰度环境限时、过滤并脱敏。它们分别帮助观察 syscall/阻塞、CPU 样本、资源压力、设备和网络；一次只验证一个假设，先止血再找根因。

## 8. P1/P2 AI、GPU 与科学评测专项

这组题用于把“会说 Transformer”补成“理解模型如何训练、如何在硬件上执行、怎样证明优化有效”。它不会把岗位变成算法岗，但能避免模型系统追问出现断层。

### 109. `[P1]` 一个 Linear 层的参数量和计算量怎样估算？

答题要点：

- 输入维度为 `d_in`、输出维度为 `d_out` 时，权重有 `d_in × d_out` 个参数，若含 bias 再加 `d_out`。
- 单个 token 的前向主计算约为 `d_in × d_out` 次 MAC（乘加）；若乘法和加法各记一次，则约为 `2 d_in d_out` FLOPs。对 `[B,T,d_in]` 输入，主矩阵计算约为 `2BT d_in d_out` FLOPs；训练还要计算输入梯度和权重梯度，主矩阵计算粗略约为前向的 3 倍，具体口径必须说明。

### 110. `[P1]` 为什么神经网络不能只堆 Linear 层？

答题要点：

- 多个纯线性变换合起来仍可化成一个线性变换，表达能力没有本质增加；激活函数加入非线性。
- ReLU、GELU、SiLU 是逐元素激活，平滑性和成本不同；SwiGLU 不是普通激活函数，而是包含两条输入投影、SiLU 与逐元素门控乘法的 FFN 结构，会改变参数量、计算量和形状。面试重点是作用与形状，不必背所有公式。

### 111. `[P1]` 残差连接和 Normalization 为什么重要？

答题要点：

- 残差让一层学习“在原表示上加什么”，也为梯度提供较直接路径；Normalization 控制激活尺度，使深层训练更稳定。
- 它们不是防止一切爆炸或消失的魔法，还要结合初始化、优化器、精度和数据观察 loss、梯度与激活分布。

### 112. `[P1]` 监督、无监督、自监督和强化学习怎样区分？

答题要点：

- 监督学习使用外部标签；无监督学习从无标签数据发现结构；自监督从数据本身构造预测目标；强化学习根据行动后的奖励优化策略。
- LLM 预训练通常是自监督 next-token prediction，SFT 使用示范标签，偏好/RL 阶段再引入比较或奖励信号；这些阶段可以组合。

### 113. `[P1]` `[红线]` GPU 的算力、显存容量和显存带宽分别限制什么？

答题要点：

- 算力决定每秒可完成多少运算；容量决定模型权重、激活与 KV Cache 能否放下；带宽决定数据在 HBM 与计算单元间搬运多快。
- 大矩阵乘可能更受算力限制，逐元素或 decode 小批次操作常更受带宽和启动开销限制；结论需结合算术强度实测。

### 114. `[P1]` 什么是 GPU kernel、fusion 和 Roofline 直觉？

答题要点：

- kernel 是一次提交到设备执行的函数；频繁启动和反复读写 HBM 都有成本。fusion 把相邻操作合并，减少中间数据搬运与启动。
- Roofline 用“每搬一个字节做多少运算”的算术强度判断更可能受计算峰值还是内存带宽上限约束。

### 115. `[P1]` FP16、BF16、FP8 和混合精度有什么取舍？

答题要点：

- 位数越少通常越省存储和带宽，并可能利用更高吞吐硬件；但动态范围、精度和硬件支持不同，会带来溢出、下溢或累计误差。
- 混合精度把敏感累加或状态保留在较高精度，把大规模矩阵计算放低精度；正确性要用训练稳定性和任务指标验证。

### 116. `[P1]` 权重量化、激活量化和 KV Cache 量化有什么不同？

答题要点：

- 它们分别压缩模型参数、算子中间值和注意力历史状态，影响的内存占比、校准难度和误差传播不同。
- 不能只说“INT8 快四倍”：实际收益受反量化、kernel、batch、硬件和带宽限制；必须同时报告质量、显存、吞吐与分位延迟。

### 117. `[P1]` LoRA、全量微调和知识蒸馏怎样选择？

答题要点：

- LoRA 冻结主权重并训练低秩增量，降低可训练参数和优化器状态；全量微调可改变全部权重，成本更高；蒸馏让学生模型学习教师输出或分布，目标是能力迁移。
- LoRA 不是模型压缩的同义词，蒸馏也不保证学生保留全部能力。选择取决于部署形态、数据、许可、训练预算和评测。

### 118. `[P2]` 数据并行、张量并行、流水线并行和专家并行在切什么？

答题要点：

- 数据并行让各 rank 处理不同数据：传统 DDP 在每卡复制完整模型，FSDP/ZeRO 等分片数据并行还会切参数、梯度或优化器状态；张量并行切一个算子中的张量；流水线并行切层；专家并行把 MoE 专家分到不同设备。
- 它们分别引入 all-reduce 或 reduce-scatter/all-gather、算子通信、流水线气泡和 all-to-all/负载倾斜。组合方案必须同时看显存、网络拓扑、通信量和故障域。

### 119. `[P1]` `[红线]` 模型置信度高，为什么仍可能错？什么是校准？

答题要点：

- softmax 概率来自模型内部相对分数，不是现实世界正确率保证；分布外输入和训练目标偏差会造成高置信错误。
- 若许多预测都报 80% 置信，其中约 80% 真的正确，才称在该分桶上较校准。Agent 仍需 verifier 和权限门禁，不能把置信度当授权。

### 120. `[P1]` 基线、消融和置信区间为什么是优化证据的底线？

答题要点：

- 基线回答“比什么好”，消融回答“提升来自哪个组件”，置信区间或重复实验回答“差异是否可能只是随机波动”。
- 除被测变量外，其余数据、Harness、模型、预算和评测器版本都要固定；只挑最好一次运行或只报一个总分，无法证明系统改进可复现。

## AI/Agent 章节口试清单（不计入 120 题）

这组清单没有题号，也不会变成第 121 题。练习方法是：每项先用 60 秒口述，再画一张最小数据流图；答不出时回到对应 AI/Agent 正文，而不是继续背关键词。

| 口试主题 | 必须能口述与画出的内容 | 不能踩的坑 |
|---|---|---|
| Transformer、Q/K/V 与 Mask | 从 Token、Embedding 到 Attention、FFN、残差和归一化；说明 Q 用来查询、K 用来匹配、V 承载被聚合信息，以及 causal mask 为什么遮住未来 Token | Q/K/V 是学习出的投影，不是三份固定数据库；mask 也不等于权限隔离 |
| 自回归与采样 | 解释 next-token 循环，以及 greedy、temperature、top-k、top-p 怎样改变候选分布 | 温度越高不保证更有创造力或更正确；温度 0 的具体行为依实现 |
| MoE、MLA 与 MTP | 区分稀疏专家路由、注意力状态压缩和多 Token 预测训练目标，并说明各自影响计算、通信或训练 | MTP 不等于服务端 speculative decoding；MoE 总参数不等于每 Token 激活参数 |
| Prefill、Decode、KV Cache、TTFT 与 TPOT | 画出请求排队、prefill 建缓存、逐 Token decode 的时间线；说明 KV Cache 为什么省计算却占显存，TTFT 与 TPOT 分别量什么 | 不能只用总延迟掩盖排队/prefill/decode，也不能把 TTFT 与 TPOT 当同一指标 |
| MCP 与工具边界 | 说明 host/client/server、工具或资源发现、schema、调用与结果返回，以及凭证和授权应由谁控制 | MCP 解决互操作，不自动信任 server、消除 prompt injection 或授予权限 |
| Memory | 区分当前上下文、短期工作状态、跨会话长期记忆与外部事实库；说明写入、检索、过期、版本和删除 | Memory 是可能过时或被污染的不可信数据，不等于模型参数或事实真相 |
| Planning 与执行 | 说明目标拆解、状态机、依赖、预算、停止条件、失败后重规划和 verifier | 更长计划不保证正确；计划文本不能越过实时权限和环境状态 |
| Multi-Agent | 说明为什么拆分、怎样分工、共享什么状态、如何合并冲突，以及权限、预算和终止怎样限制 | Agent 越多不必然越强，还会增加通信、重复工作、级联错误和成本 |
| RAG、索引与权限 | 画出采集、清洗、切分、embedding/倒排索引、召回、混合检索、rerank、上下文组装和生成；说明增量更新、删除与 ACL 过滤 | 相似不等于相关，召回结果不等于可信事实；权限过滤不能等生成后再补 |
| 模型网关 | 说明模型路由、版本、限流、预算、超时、重试、fallback、流式响应、观测和租户隔离 | fallback 会改变质量与语义；模型调用超时和重试也要考虑重复计费及未知结果 |
| 自进化闭环 | 画出轨迹采集、失败归因、数据/规则/Prompt/策略候选、离线评测、消融、门禁、灰度、回滚和新失败回流 | 不能让同一个有缺陷的 evaluator 同时出题、打分和决定上线，也不能只报最好一次结果 |

## 9. P2 开放追问：没有唯一标准答案

这些题不计入 120 道编号题，也不要求临近面试时全做。它们用来训练“先定义约束，再提出方案和验证”的能力：

- 同一平台需要同时运行 Linux 与 Windows guest，你会怎样划分镜像、设备模型、补丁、快照和故障域？
- 什么时候值得把 `epoll` 路径换成 `io_uring`？请给出可证伪的 benchmark 设计，而不是只列优点。
- 跨三个地域的 Agent 控制面，任务状态、审计事件和大制品应采用相同一致性协议吗？为什么？
- 如果量化使模型吞吐提高 30%，但工具 JSON 失败率上升 0.2%，怎样决定是否上线？
- Multi-Agent 在什么条件下比单 Agent 更值得？怎样用消融实验区分能力提升与预算增加？
- 设计一次不会危及宿主机的 OOM、网络分区或存储长尾演练，写出清理、停止和观测边界。
- 面试官给出一个你没见过的虚拟化或 GPU 名词时，怎样从接口、资源、失败模式和证据四步推导？

## 10. 常见失分点

- 只给定义，不说它解决哪个失败模式。
- 答案出现十个组件名，却没有状态、数据流和信任边界。
- 一说“幂等”就声称 exactly-once，一说“容器”就声称安全。
- 性能数字没有分母、样本、硬件和阶段边界。
- 把模型判断当最终授权或最终 verifier。
- 论文状态、团队贡献或项目数字表述失真。
- 未知问题强行作答；承认边界后给验证方法通常更专业。
- 每题都套同一个项目，导致无法展示研究、开源、数据链路和教学的不同侧面。

## 11. 本章速记

- 120 题分为：24 道共同基础、20 道深入、14 道故障、10 道容量、12 道行为、28 道系统地基和 12 道 AI/GPU/评测专项。
- 先过 P0，再补 P1；P2 用于方向相关的开放追问，不要求在临近面试时平均背诵。
- 技术题四步：**定义 → 失败模式 → 方案/取舍 → 验证与限制。**
- 经历题六步：**问题 → 不变量 → 本人行动 → 验证 → 结果 → 限制。**
- 高频关键词不是装饰：幂等、租约、背压、verifier、trace、最小权限都要能画出机制。
- 每天随机抽 10 题：30 秒结论、2 分钟展开、再承受 3 次追问；每三天至少做一次 30 题跨层抽测。
- 系统题回到[DSec 白板](system_design.md)，事实题回到[简历深挖](resume_drill.md)，冲刺节奏见[学习计划](study_plan.md)。
