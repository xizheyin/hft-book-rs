# 术语表：把黑话翻译成人话

这份术语表不是让你背定义，而是帮助你在章节之间快速找回共同语言。面试时先说它解决什么问题，再补机制；只念英文缩写通常拿不到分。

使用顺序：Agent Infra freshman 先查第 5～6 节中与进程、网络、文件、分布式、沙箱、SLO 有关的词，再查第 3 节 Agent/Harness；模型训练、特定架构、GPU 格式和检索索引只在正文或面试追问出现时查阅。这里出现一个词不代表它自动成为 P0，也不要求背英文全称。

## 1. 模型与训练

| 术语 | 通俗解释 | 容易说错的地方 |
|---|---|---|
| AI | 让机器完成通常需要智能的任务的总称 | AI 不等于大语言模型 |
| Machine Learning | 从数据中学习规律，而不是把每条规则手写出来 | 学到相关性不等于因果性 |
| Deep Learning | 使用多层神经网络的机器学习方法 | “层数多”不是唯一特征 |
| LLM | 在大量文本/代码上训练的语言模型 | 模型本身不包含工具权限和持久状态 |
| Token | 模型处理文本的离散单位 | 不一定是一个字或一个单词 |
| Tokenizer | 把文本与 Token ID 相互转换的规则和程序 | 换 tokenizer 会改变长度与模型输入 |
| Embedding | 把离散对象映射成连续向量 | 向量相近不保证事实等价 |
| Linear Layer | 用矩阵乘和偏置把输入维度映射到输出维度 | 多层纯 Linear 仍等价于一层线性变换 |
| Activation | 给网络加入非线性的逐元素函数，如 ReLU、GELU、SiLU | 激活函数不是越复杂越好 |
| FFN | Transformer 中逐 Token 进行升维、激活和降维的前馈网络 | 不负责 Token 之间直接通信 |
| Normalization | 调整一组激活的尺度以帮助稳定训练 | LayerNorm、RMSNorm 的统计量与位置并不相同 |
| Logit | softmax 前的未归一化分数 | 不是概率，也不必落在 0 到 1 |
| Softmax | 把一组分数转成和为 1 的分布 | 数值稳定实现会先减最大值 |
| Loss | 用一个数衡量预测和目标的差异 | loss 下降不等于线上目标一定改善 |
| Gradient | loss 对参数变化的局部方向提示 | 梯度是局部信息，不保证一步到全局最优 |
| Backpropagation | 沿计算图反向用链式法则算梯度 | 它算梯度，优化器才更新参数 |
| Batch | 一次并行处理的一组样本/请求 | 训练 batch 与推理 continuous batch 语境不同 |
| Epoch | 训练数据大致完整走过一遍 | 流式海量数据中未必是最有用单位 |
| Overfitting | 记住训练样本，遇到新数据表现变差 | 训练分高不是泛化证据 |
| Regularization | 限制模型过度贴合训练数据的方法 | 不是只有 L2 一种 |
| Pretraining | 在大规模数据上学习通用预测能力 | 不是面向单个应用的最后一步 |
| SFT | 用“输入-理想输出”样本做监督微调 | 主要模仿示范，不直接优化所有长期结果 |
| LoRA | 冻结主权重，只训练低秩增量矩阵的参数高效微调方法 | 不是量化，也不自动缩小最终基础模型 |
| Distillation | 让较小学生模型学习教师模型输出或分布 | 学生不会自动保留教师全部能力 |
| Preference Alignment | 用偏好比较让模型更符合期望 | “更符合偏好”不等于事实更正确 |
| RLHF | 从人类反馈构造奖励并用强化学习优化 | 是一类流程，不等于某一个固定算法 |
| RLVR | 用可验证奖励做强化学习 | verifier 错了，模型会优化错误目标 |
| PPO | 使用裁剪目标限制策略更新幅度的算法 | 细节多，面试先讲旧/新策略稳定更新直觉 |
| GRPO | 通过同题一组输出的相对奖励形成优势信号 | 不是 Agent 平台所有问题的通用解法 |
| Rollout | 让当前策略在环境里完整或分段执行得到轨迹 | 轨迹包含环境、工具和奖励版本 |
| Calibration | 让模型报告的置信程度与长期真实正确率大致对应 | 高置信度不天然代表已校准或正确 |
| Ablation | 移除或替换一个组件，判断提升到底来自哪里 | 一次改多个因素无法归因 |

## 2. Transformer 与推理

| 术语 | 通俗解释 | 容易说错的地方 |
|---|---|---|
| Self-Attention | 每个 Token 按内容选择从其他 Token 读取多少信息 | attention 权重不是可靠解释 |
| Q/K/V | 查询、键和值三组表示 | 类比帮助理解，实际都是学习出的投影 |
| Multi-Head Attention | 多组注意力并行学习不同关系 | 头数更多不保证效果更好 |
| Positional Encoding | 给模型加入顺序信息 | 不同模型可能用不同方法 |
| Residual Connection | 给深层变换保留一条直接通路 | 不能单独消除所有训练不稳定 |
| Autoregressive Decode | 每次基于已有上下文生成下一个 Token | 前一步错误会进入后续上下文 |
| Prefill | 一次处理输入上下文并建立初始缓存 | 常更偏并行计算密集 |
| Decode | 逐步生成新 Token | 常更受内存带宽和调度影响 |
| KV Cache | 保存历史 Token 的 Key/Value，避免每步重复计算 | 省计算但吃显存/内存，并有生命周期问题 |
| TTFT | 从请求到第一个输出 Token 的时间 | 包含排队和 prefill，不只是模型计算 |
| TPOT | 首 Token 后生成每个 Token 的时间 | 需说明统计口径和批处理条件 |
| Continuous Batching | 请求在不同 decode 步动态加入或离开 batch | 提升吞吐也可能改变排队与公平性 |
| Prefix Cache | 复用相同前缀的推理中间结果 | cache key 必须包含模型和影响语义的配置 |
| Temperature | 缩放 logits，影响采样分布的平或尖 | 温度 0 的具体行为依实现，别绝对化 |
| Top-k | 只在最高的 k 个候选中采样 | k 固定，不适应分布形状 |
| Top-p | 取累计概率达到 p 的最小候选集合 | 通常与 temperature 共同影响结果 |
| MoE | 每个 Token 只激活部分专家的稀疏模型 | 总参数大不等于每 Token 都算全部参数 |
| Expert Parallelism | 把不同专家放在不同设备上 | 路由会产生 all-to-all 通信和负载不均 |
| MLA | 将注意力相关状态压缩到潜表示以降低缓存/计算压力的架构 | 要以 DeepSeek 官方技术报告的具体定义为准 |
| MTP | 训练时预测多个未来 Token 的辅助目标 | 不应和服务侧 speculative decoding 混为一谈 |
| Quantization | 用更低位宽表示权重或激活 | 节省资源可能带来精度和内核支持风险 |
| HBM | GPU 旁的高带宽显存，保存权重、激活和 KV Cache | 高带宽不等于无限容量或零延迟 |
| GPU Kernel | 一次提交到 GPU 上并行执行的函数 | kernel 数量少不必然更快，仍看数据移动与占用率 |
| Kernel Fusion | 合并相邻操作以减少启动和中间数据搬运 | 会增加实现与编译复杂度，必须实测 |
| Tensor Core | GPU 中面向特定低精度矩阵运算的专用计算单元 | 只有形状、数据类型和软件栈匹配时才能充分利用 |
| Roofline | 用算术强度判断工作更可能受算力还是带宽限制的模型 | 是上界直觉，不是准确延迟预测器 |
| Mixed Precision | 不同计算或状态采用不同数值精度 | 需要验证溢出、下溢与累计误差 |
| FP16 / BF16 / FP8 | 不同位宽和指数/尾数分配的浮点格式 | 位宽更低不代表所有硬件和算子都更快 |

## 3. Agent 与 Harness

| 术语 | 通俗解释 | 容易说错的地方 |
|---|---|---|
| Agent | 模型在循环中读取状态、选择动作、调用工具并根据结果继续 | 不是“多写一个 Prompt” |
| Harness | 把模型接到上下文、工具、状态、预算、验证与用户体验的系统外壳 | DeepSeek 官方相邻岗概括为 Model + Harness = Agent |
| Agent Loop | 观察、模型决策、动作、结果、更新与终止的循环 | 必须有预算和确定性终止条件 |
| Tool Use | 模型提出结构化工具调用，由系统校验和执行 | 模型不能直接获得工具底层凭证 |
| MCP | 连接 AI 应用与工具/资源的一套开放协议 | 协议解决互操作，不自动解决信任与授权 |
| Skill | 面向特定任务的说明、规则、样例和脚本等能力包 | 自然语言 Skill 也应版本化和测试 |
| Prompt Engineering | 设计指令与样例以影响模型行为 | 不能代替后端安全控制 |
| Context Engineering | 选择、组织、压缩和标注当前模型可见信息 | 上下文越长不一定越好 |
| Memory | 跨步骤或跨会话保存并取回的信息 | Memory 是不可信持久数据，不等于模型参数 |
| Planner/Executor | 分离任务拆解与具体执行 | 分离会增加延迟和状态同步成本 |
| Subagent | 由主 Agent 委派的受限执行主体 | 权限、预算和终止不能无限继承 |
| Multi-Agent | 多个 Agent 通过协议协作 | 更多 Agent 可能增加协调成本和错误传播 |
| Human-in-the-loop | 在高风险或不确定节点由人审批/接管 | 审批必须绑定具体参数，不能一批到底 |
| Checkpoint | 保存可恢复的执行状态 | 需要与外部副作用和版本一致 |
| Verifier | 对结果做相对确定的检查程序或规则 | verifier 本身也可能有缺陷 |
| Golden Set | 人工确认并版本化的代表性评测集合 | 要防污染并持续补充新失败 |
| Paired Evaluation | 控制其他条件，对有/无某因素的两次运行做对照 | 模型随机性和环境版本需控制 |

## 4. 检索与数据

| 术语 | 通俗解释 | 容易说错的地方 |
|---|---|---|
| RAG | 先检索外部材料，再把材料放入上下文生成 | 失败可能在采集、检索、上下文或生成任一层 |
| Sparse Retrieval | 依赖词项匹配的检索，如 BM25 | 对精确名词强，不等于“落后方法” |
| Dense Retrieval | 用向量相似度召回 | 语义相近可能事实无关，权限过滤不能省 |
| Hybrid Retrieval | 组合稀疏与稠密信号 | 需要校准和去重，不是简单拼列表 |
| Reranker | 对初召回候选做更精细排序 | 更准但增加成本和延迟 |
| Chunking | 把长文档切成可索引片段 | 过小丢语境，过大稀释相关信息 |
| Data Leakage | 训练或评测看到本不该看到的未来/答案信息 | 会制造虚假的高分 |
| Distribution Shift | 线上输入与开发时分布变化 | 可能来自用户、工具、模型或业务改变 |

## 5. 系统与可靠性

| 术语 | 通俗解释 | 容易说错的地方 |
|---|---|---|
| User Mode / Kernel Mode | 应用受限运行与内核掌握全局资源的两种权限级别 | 进入内核不一定发生线程上下文切换 |
| Process | 拥有独立地址空间和资源视图的执行容器 | 进程不是正在运行的单个函数 |
| Thread | 调度器可运行的执行流，同进程线程共享多数资源 | 每个线程仍有自己的栈和寄存器 |
| System Call | 用户程序请求内核服务的受控入口 | syscall 次数多不等于它一定是瓶颈 |
| Context Switch | CPU 从一个线程切到另一个线程并保存/恢复状态 | 与用户态/内核态切换不是同义词 |
| File Descriptor | 进程内索引内核打开对象的小整数 | 它可代表 socket、pipe 等，不只是磁盘文件 |
| Virtual Memory | 用页表把每个进程的虚拟地址映射到物理页 | 虚拟地址空间大不等于已占用同量物理内存 |
| Page Table | 保存虚拟页到物理页及权限的分层映射 | 页表本身也占内存，并需要内核维护 |
| TLB | CPU 缓存最近地址翻译的表 | miss 不等于磁盘缺页 |
| Page Fault | 访问尚未建立有效映射的页面时进入内核处理 | minor fault 可能完全不需要磁盘 I/O |
| COW | 多方先共享只读页，首次写入时再复制 | 首次写会制造缺页、内存和延迟尖刺 |
| OOM | 内存需求无法满足时的系统或 cgroup 处理 | 不能只凭 `free` 一列判断风险 |
| Mutex | 争用时让等待者睡眠的互斥同步原语 | 持锁做慢 I/O 容易放大长尾 |
| Atomic | 对某个内存位置不可分割的操作 | 单个操作原子不等于整个并发算法正确 |
| Memory Ordering | 约束多核观察内存读写先后关系的规则 | relaxed 也有语义，不是“完全无序” |
| futex | 无争用走用户态、争用时借内核睡眠/唤醒的机制 | 只是构建锁的底层工具，不自带公平性 |
| epoll | Linux 上批量等待文件描述符就绪的接口 | 就绪后应用通常仍要执行非阻塞 I/O |
| io_uring | 用共享提交与完成队列表达异步 I/O 的 Linux 接口 | 不是所有负载和内核版本都更快或更安全 |
| IP | 跨网络寻址和转发数据报的网络层协议 | IP 是尽力而为，不保证送达、顺序或只送一次 |
| Route | 根据目标地址前缀选择出口和下一跳的规则 | 有路由不等于后续策略、邻居和远端都可用 |
| ARP | 在本地 IPv4 链路上把 IP 地址解析为链路层地址 | 跨网段时通常解析网关，不是远端主机本身 |
| TCP Flow Control | 用接收窗口避免压垮接收方 | 不等于保护整条网络路径的拥塞控制 |
| TCP Congestion Control | 根据网络反馈调整在途数据 | 重传能恢复丢包，但会增加延迟和带宽 |
| DNS | 把名称解析成地址等记录的分布式命名系统 | 缓存、负缓存和多级解析都会影响故障表现 |
| TLS | 对连接建立身份验证、加密与完整性保护 | 加密连接不代表应用请求已获业务授权 |
| HTTP/1.1 | 使用文本式消息格式承载 HTTP 语义的协议版本 | 一次写入不等于一个完整请求，连接复用也要处理边界 |
| HTTP/2 | 使用二进制分帧并在一条连接上复用多个 stream | TCP 层丢包仍可能让多条 stream 一起等待 |
| QUIC | 基于 UDP 构建可靠传输、多路 stream、拥塞控制，并集成 TLS 1.3 握手的传输协议 | “基于 UDP”不等于它不可靠；连接迁移与 0-RTT 也有额外状态和安全约束 |
| HTTP/3 | 把 HTTP 语义映射到 QUIC 的协议版本 | 不再受 TCP 跨 stream 队头阻塞，不等于单个 stream、拥塞或应用处理永远不会阻塞 |
| gRPC | 常基于 HTTP/2 的强类型 RPC 框架 | deadline、幂等和重试仍需业务设计 |
| L4 / L7 Load Balancer | 分别按连接元数据或应用协议内容转发 | 健康检查通过不等于服务有真实处理能力 |
| Sandbox | 对不可信工作负载施加强制边界的环境 | 不是某一个产品名，也不是绝对安全 |
| Namespace | 限制进程看到的系统视图 | 不负责完整资源限额 |
| cgroup | 统计和限制一组进程的资源 | 不提供独立内核安全边界 |
| seccomp | 过滤进程可用的系统调用 | 单独使用不是完整隔离 |
| Linux Security Module（LSM） | Linux 内核提供安全钩子的框架，SELinux、AppArmor 等安全模块可借此实施对象访问策略 | 这里的 LSM 是安全框架，与存储中的 LSM-tree 完全无关；它也不能单独构成完整沙箱 |
| VMM | 创建和管理虚拟机的监控器 | VMM 仍有攻击面和版本风险 |
| vCPU | 提供给虚拟机的“逻辑 CPU”；宿主调度器最终把它安排到物理 CPU 上运行 | 一台 VM 有 8 个 vCPU，不代表它始终独占 8 个物理核心 |
| Hardware Virtualization | CPU 为运行 guest 和受控切回 VMM 提供的硬件机制 | 硬件辅助能缩小模拟成本，但不会消除 VM exit 与共享资源竞争 |
| VM Entry / Exit | CPU 进入 guest 执行，以及因中断或敏感操作返回 VMM 的边界切换 | exit 太频繁会付出切换和设备处理成本，不能只看 guest 内部 CPU 使用率 |
| Second-stage Translation | 在 guest 页表翻译后，再把 guest 物理地址翻译到宿主物理地址；Intel EPT、AMD NPT 是常见实现 | 它加强内存虚拟化，但增加 TLB、页表遍历和缺页排查层次 |
| virtio | guest 与 VMM 约定的半虚拟化设备接口，用共享队列减少逐条设备模拟成本 | 仍需要驱动、通知、中断和后端处理，不等于 I/O 没有开销 |
| Dirty-page Tracking | 记录快照或迁移期间哪些 guest 内存页又被修改 | 只跟踪内存脏页不能自动保证磁盘、网络和外部副作用一致 |
| NUMA | CPU 访问本地内存通常比访问另一个插槽的远端内存更快的硬件拓扑 | vCPU 和内存放置不匹配可能增加长尾；不能只按总核数和总内存调度 |
| microVM | 精简设备与功能、面向高密度场景的轻量 VM | 仍然是 VM，不是容器别名 |
| VFS | Linux 虚拟文件系统层，为不同具体文件系统提供统一接口 | `write()` 返回不等于数据已经持久化 |
| NVMe | 常见的高速非易失存储协议 | 协议快不代表文件系统同步语义自动满足 |
| veth / TAP | veth 是成对虚拟网卡；TAP 把二层帧交给用户态程序 | 它们只是单机接入点，不是完整虚拟网络 |
| CNI | 容器网络接口规范，让运行时调用插件配置网络 | CNI 是接口规范，不是某一个数据面 |
| eBPF | Linux 内核中的受约束可编程机制，可做网络、观测与安全 | 使用 eBPF 不自动保证低延迟或正确策略 |
| MTU | 一条链路无需分片可承载的最大包尺寸 | overlay 封装会吃掉一部分 MTU |
| NAT / conntrack | 地址转换，以及记录连接状态的跟踪机制 | 大规模连接可能先耗尽端口或状态表 |
| Control Plane | 保存意图、调度并协调资源 | 不应把每个数据包放进控制面处理 |
| Data Plane | 真正执行计算、网络、存储和策略 | 控制面记录允许不等于数据面已强制 |
| Reconciliation | 比较期望与实际状态并反复收敛 | 每一步必须幂等且有停止条件 |
| Idempotency | 同一逻辑操作重复执行，业务结果不再额外变化 | HTTP 方法名不能自动提供业务幂等 |
| Lease | 一段有限时间的所有权 | 过期旧主人可能仍运行，需要 fencing |
| Fencing Token | 单调版本票据，数据面拒绝旧持有者 | 只在控制面比较不够 |
| Backpressure | 下游过载信号向上游传播 | 无界队列只是延迟失败 |
| Quorum | 多副本操作等待其中一部分确认 | 多数派不自动等于所有业务线性一致 |
| SLI/SLO/SLA | 测量/内部目标/外部承诺 | 三者不能混用 |
| Error Budget | SLO 允许的失败额度 | 不是鼓励制造故障，而是发布取舍机制 |
| RTO/RPO | 故障后恢复时间/可接受数据丢失窗口 | 需要真实恢复演练验证 |
| Blast Radius | 一次故障能影响多大范围 | 自动化也必须限制影响半径 |

## 6. 文件系统、数据库与分布式基础

| 术语 | 通俗解释 | 容易说错的地方 |
|---|---|---|
| inode | 保存文件元数据与数据位置的文件系统对象 | 文件名通常存在目录记录中，不在 inode 本体 |
| dentry | 内核对路径组件到文件对象映射的缓存结构 | 它不是持久化到磁盘的普通目录文件格式 |
| Journal | 先记录可恢复更新，再修改文件系统主体的日志机制 | 有 journal 不代表应用数据已按业务语义持久化 |
| Page Cache | 内核用内存缓存文件数据的机制 | `write()` 进入页缓存不等于掉电安全 |
| Block Layer | 在文件系统与设备驱动之间组织块 I/O 的层次 | 应用请求可能在这里合并、排队或重排 |
| WAL | 数据库修改主体数据前先写的恢复日志 | 底层文件系统 journal 不能替代数据库 WAL |
| Transaction | 把一组操作作为定义好的提交/回滚单元 | ACID 每个字母仍依赖具体隔离级别和故障模型 |
| MVCC | 保存多版本，让读者按快照查看数据 | 旧版本需要回收，长事务可能阻碍清理 |
| B-tree | 保持平衡、适合点查和范围扫描的索引树 | “树高低”不是全部成本，还要看缓存与写放大 |
| LSM-tree（Log-Structured Merge-tree） | 先写内存与日志，再把有序数据后台合并到多层的存储结构 | 这里的 LSM 指 Log-Structured Merge，与 Linux Security Module 无关；compaction 会带来读写放大和尾延迟 |
| happens-before | 用进程内顺序、消息发送/接收和传递性描述因果先后 | 逻辑时间戳较小不必然证明因果 |
| Linearizability | 每次操作看起来在调用和返回之间某一瞬间生效 | 与事务 serializability 不是同一个维度 |
| Eventual Consistency | 停止新更新后，副本最终收敛 | 不承诺收敛前读到哪个版本或多久收敛 |
| Replication | 把数据复制到多个故障域 | 多副本不自动带来正确故障切换 |
| Consensus | 多节点在故障下就某个值或日志顺序达成一致 | 不能绕过网络分区和多数派要求 |
| Raft | 通过 leader、任期、多数投票与复制日志实现共识的协议 | Raft 不替应用决定业务事务或外部 fencing |
| CAP | 分区发生时，原子一致性与每个请求最终得到规范响应的可用性不能同时保证 | 不是正常运行时简单“三选二” |
| 2PC | 协调者先让参与者 prepare，再决定 commit/abort 的两阶段提交 | 协调状态和悬挂事务需要恢复，不能覆盖任意 HTTP 副作用 |
| Outbox | 把业务更新和待发布事件写进同一事务，再异步投递 | 消费者仍需幂等，投递仍可能重复 |
| Saga | 把长事务拆成步骤与补偿动作 | 补偿不是时间倒流，也可能失败 |
| Sharding | 按范围、哈希或目录把 key 空间分给多个组 | 带来热点、再平衡与跨分片协调 |
| Split Brain | 分区或故障检测错误导致多方同时自认拥有写权 | 只做 leader 选举不一定能保护协议外资源 |
| Little's Law | 稳态下平均在途量 `L = 到达率 λ × 停留时间 W` | 平均公式不能表达突发和重尾分布 |
| Tail Latency | 延迟分布最慢一端，如 p99、p999 | 平均延迟正常不能证明用户体验正常 |
| Coordinated Omission | 压测器随系统变慢而少发请求，漏记真实等待 | 会系统性美化尾延迟结果 |
| PSI | Linux 统计 CPU、内存和 I/O 压力造成等待的指标 | 资源利用率与等待压力不是同一件事 |
| strace | 观察进程系统调用、信号和返回错误的工具 | 会扰动时序并可能记录敏感参数 |
| perf | 基于计数器和采样分析 on-CPU 行为的 Linux 工具集 | 样本归属不自动证明根因 |
| iostat | 查看块设备吞吐、队列和等待趋势的 sysstat 工具 | 宿主设备指标还需关联到目标进程和 cgroup |
| ss | 查看 socket 状态、队列和 TCP 信息的工具 | 单次快照不能代替请求级 trace |
| tcpdump | 按过滤条件抓取网络包的工具 | 需要授权、限接口/时长/包数并保护捕获数据 |

## 7. 面试使用方法

遇到陌生缩写时，可以用四句话组织：

1. 它要解决什么问题？
2. 最小工作机制是什么？
3. 它换来了什么，又付出什么？
4. 在 Agent Infra 哪个环节会看到它？

如果第四句答不出，说明你记住了词，却还没把它放进系统。
