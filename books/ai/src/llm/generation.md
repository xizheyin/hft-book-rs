# 文本生成：Temperature、Top-p 与每一步的选择

把语言模型想成每写一个字都重新拿到一张菜单。菜单列出所有候选 Token 及其分数：总选最高分，文章可能稳定却呆板；偶尔按概率尝试其他高分项，表达会更多样；如果连极低概率的怪菜也允许点，结果就可能失控。Temperature 和 Top-p 不是让模型“更聪明”的按钮，而是改变这张菜单怎样被抽样。

> 本章目标：理解自回归生成、Greedy、Temperature、Top-k、Top-p、停止条件和结构化输出，并能解释解码参数怎样影响 Agent 的质量、复现性与资源占用。

## 1. 自回归生成循环

自回归模型一次生成一个 Token：

```text
上下文 → 模型 → 下一个 Token → 追加到上下文 → 再次运行模型
```

伪代码如下：

```text
tokens = tokenize(prompt)
repeat until stop:
    logits = model(tokens)
    next = decode(logits[-1], config)
    tokens.append(next)
return detokenize(tokens)
```

第 `t+1` 个 Token 依赖已经选出的前 `t` 个 Token。早期一次低概率选择可能改变整条后续路径，所以相同问题的两个样本可能越写越不一样。

## 2. Greedy：每次都选最高分

Greedy Decoding（贪心解码）每一步选择概率最高的 Token。优点是简单、通常较稳定；缺点是局部最高不保证整段最好，开放式文本还可能重复或过于模板化。

Beam Search 同时保留多条累计得分较高的候选路径，适合部分有明确输出结构的任务，但内存与计算随 Beam 数增加，而且在开放式对话中不一定比采样自然。

Agent 工具选择并不一定要依赖普通 Greedy。更可靠的系统会约束允许的函数名和 JSON 结构，并在执行前进行确定性验证。

## 3. Temperature：改变分布的尖锐程度

Temperature（温度）在 Softmax 前缩放 Logit：

```text
p_i = softmax(z_i / T)
```

仍以 Logit `[2, 1, 0]` 为例：

| 温度 T | 概率（约） | 直觉 |
|---:|---|---|
| 0.5 | `[0.867, 0.117, 0.016]` | 更集中，首选更容易被选中 |
| 1.0 | `[0.665, 0.245, 0.090]` | 原始 Softmax |
| 2.0 | `[0.506, 0.307, 0.186]` | 更平坦，低分项机会增加 |

严格代数上 `T=0` 会除零。许多推理 API 把“温度 0”实现为 Greedy 或特殊确定性路径，必须以具体服务契约为准。

低温不等于事实正确，高温也不等于创造力有保证。温度只重排已有 Logit 分布；模型没有证据时，低温可能只是更稳定地输出同一个错误。

## 4. Top-k：只保留固定数量候选

Top-k 先保留概率最高的 `k` 个 Token，将其余概率设为 0，再归一化抽样。

若概率为：

```text
[0.55, 0.25, 0.10, 0.06, 0.04]
```

设置 `top_k = 2` 后只保留前两个，归一化为：

```text
[0.55/0.80, 0.25/0.80] = [0.6875, 0.3125]
```

固定 `k` 的问题是：模型很确定时 50 个候选可能太多，模型很犹豫时 5 个候选又可能太少。

## 5. Top-p：保留累计概率核心

Top-p，也叫 Nucleus Sampling（核采样），按概率从高到低排序，保留累计概率达到阈值 `p` 的最小候选集合。

仍用：

```text
[0.55, 0.25, 0.10, 0.06, 0.04]
```

若 `top_p = 0.80`，前两个累计恰好为 `0.80`，只在这两个中抽样。若分布更平坦，达到 0.80 就需要更多 Token，因此候选集合能随模型不确定程度变化。

实现的边界细节可能不同，例如是否包含刚刚越过阈值的 Token。对严格回归测试，应锁定推理引擎及版本，而不是只保存一个 `top_p` 数字。

## 6. 参数怎样组合

常见顺序可概括为：

```text
Logit 处理 → Temperature → Top-k/Top-p 截断 → 归一化 → 抽样
```

具体引擎还可能加入重复惩罚、频率惩罚、最小概率、禁止 Token 和语法约束。处理顺序会影响结果，所以请求日志至少记录：

- 模型和 Tokenizer 版本；
- Temperature、Top-p、Top-k；
- 最大输出 Token 数；
- 停止 Token 或停止字符串；
- 随机种子（若引擎支持）；
- 结构化输出或 Grammar 配置；
- 推理引擎及关键版本。

## 7. 停止条件也是正确性条件

生成通常在以下任一条件发生时停止：

1. 生成 EOS（序列结束）Token；
2. 命中指定 Stop Sequence；
3. 达到 `max_new_tokens`；
4. 客户端取消或服务超时；
5. 安全策略中止。

“达到最大长度”不等于正常完成。Agent 生成 JSON 时若在右花括号之前被截断，系统必须把它标记为不完整，而不能尝试执行半个动作。

### 一个延迟与成本算例

若首 Token 延迟为 300ms，之后每个 Token 平均 25ms，生成 101 个 Token 的近似时间是：

```text
总延迟 ≈ 300ms + (101 - 1) × 25ms = 2.8s
```

把 `max_new_tokens` 从 200 提高到 2,000，不只改变答案长度上限，也扩大了最坏执行时间、KV Cache 占用和租户成本。

## 8. Agent 场景怎样选择解码策略

| 场景 | 常见倾向 | 仍需的系统保护 |
|---|---|---|
| 工具名与参数 | 低随机性、结构约束 | Schema、权限、语义校验 |
| 代码补丁 | 较低到中等随机性，可生成多个候选 | 编译、测试、沙箱 |
| 头脑风暴 | 允许更高多样性 | 去重、排序、事实核验 |
| 最终事实回答 | 不能靠低温保证正确 | 检索、引用、校验 |
| 评测回归 | 固定配置和版本，多次采样 | 报告分布而非单次结果 |

可以为“计划”和“执行参数”采用不同策略：计划阶段允许探索多个方案，真正的工具参数则必须通过受限解码和确定性验证。

## 9. 可复现性为什么比一个 Seed 复杂

固定随机种子可以控制抽样随机数，但不必然保证跨环境逐 Token 相同。差异还可能来自：

- 模型或 Tokenizer 权重不同；
- 浮点精度和并行归约顺序；
- GPU Kernel 或推理引擎版本；
- 动态批处理改变执行顺序；
- 相近 Logit 在数值误差后交换排名；
- 服务端默认参数改变。

因此，Agent 回放应保存原始输入、配置、模型版本、工具结果和最终 Token/动作；不能只保存 Prompt 和 Seed。

## 10. 一条典型失败路径：看似合法的半截 JSON

模型准备调用工具：

```json
{"path":"/safe/project","operation":"archive"
```

请求达到长度上限，缺少右花括号。危险的运行时可能用宽松解析器“修复”后直接执行。更安全的流程是：

1. 将停止原因标记为 `length`，不是 `completed`；
2. 严格解析完整 Schema；
3. 校验枚举、路径和权限；
4. 对有副作用动作要求幂等键或审批；
5. 失败时可以请求模型重新生成，但不能把重试当作校验。

另一类常见失败是重复循环。提高重复惩罚可能缓解表象，却不一定修复根因；还应检查 Prompt、上下文污染、停止条件和模型是否缺少完成状态。

## 11. DeepSeek Agent Infra 面试怎么问

### 30 秒答法

> 自回归模型每一步根据已有 Token 输出下一步 Logit。Temperature 调整分布尖锐度，Top-k 保留固定数量候选，Top-p 保留累计概率核心后再抽样。它们改变多样性，不保证事实性。Agent 的工具调用应使用结构约束和低随机性，但真正安全来自 Schema、权限、幂等和执行后校验；还要记录停止原因、模型版本与解码配置。

### 追问 1：Temperature 越低是否越正确？

不是。它让高 Logit Token 更占优势，只提高选择稳定性。模型本身把错误答案排第一时，低温会稳定地重复错误。

### 追问 2：Top-k 和 Top-p 怎么选？

Top-k 固定候选数量，Top-p 随分布集中程度动态改变集合。开放生成常用 Top-p，但选择必须通过任务评测，不能脱离模型和其他参数给万能值。

### 追问 3：温度 0 为什么仍可能不完全复现？

服务通常走 Greedy，但浮点并行、Kernel、模型版本和动态批处理仍可能让非常接近的 Logit 排名变化。端到端复现需要锁定环境并保存轨迹。

### 追问 4：工具调用 JSON 能解析就可以执行吗？

不可以。语法合法不代表语义、安全和权限合法，还要检查停止原因、Schema、路径/资源边界、调用者权限、幂等和高风险审批。

## 12. 本章速记

- 自回归生成一次选一个 Token，早期选择会改变后续路径。
- Greedy 每步选最高分；稳定不等于全局最优或事实正确。
- 低 Temperature 使分布更尖，高 Temperature 使分布更平。
- Top-k 固定候选数，Top-p 按累计概率动态决定候选集合。
- 停止原因是协议的一部分；长度截断不能冒充完成。
- `max_new_tokens` 同时影响延迟、缓存和成本上界。
- Seed 只能控制部分随机性；可靠回放还要保存版本、配置和工具轨迹。
- Agent 工具调用必须在解码之后继续做确定性校验。
