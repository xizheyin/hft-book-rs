# AI Infra 需要哪些系统基础

AI Infra 是“让模型和 Agent 稳定运行的平台”。这里的 Agent 指能够调用工具、读写状态并分步骤完成任务的程序。它最终仍然运行在进程、内存、网络和存储之上，所以理解系统基础很重要。

但是，同一套操作系统原理不应该在两本书里重复讲。本节只解释 **Agent 场景多出来的问题**；通用基础统一放在第一册《系统、Rust、C++ 与 HFT 基础宝典》。这样读者只学一次概念，再学习它在不同岗位里的应用。

## 本节只讲五类 Agent 增量

1. **执行边界**：任务不是一个 PID，而可能是一棵会继续创建子进程的进程树。
2. **资源边界**：内存、进程数、输出、网络和存储都必须有可执行的上限。
3. **不确定结果**：超时只表示调用方没有按时得到答案，不表示操作没有发生。
4. **可恢复状态**：worker 崩溃后，平台需要知道任务做到哪一步，以及哪些副作用已经发生。
5. **多租户影响**：多个用户共享机器时，一个任务不能无限挤占其他任务的资源。

后续每章都按“问题是什么 → 为什么 Agent 特别需要 → 最小正确设计 → 面试回答”展开。底层实现名词只在它能解释设计选择时出现，不要求背内核调用栈或产品配置。

## 面试时怎样使用这些知识

面试官通常不期待候选人从零实现内核或共识协议。更常见的要求是：

- 先说清当前对象，例如“一个 Agent run 的整棵进程树”，而不是含糊地说“任务”。
- 再说清失败边界，例如“进程已被杀，但外部付款请求可能已经成功”。
- 最后给出可验证的设计，例如用有界输出、幂等键、状态机和资源指标证明系统能够恢复。

如果答案中出现一个新名词，应立刻补一句“它是什么、为什么此处需要它”。这也是本节所有章节采用的讲解标准。
